# Ближайшие задачи для команды

Задачи подготовлены для передачи участникам. Внешние сообщения и GitHub Issues не отправлялись. Qwen/MLX и проверку качества типов ведёт Агыбай; повторять этот эксперимент другим участникам не нужно. Ниже — отдельные результаты, которые можно делать параллельно. Объём первого подхода — ориентировочно 2–4 часа, без обещания закончить весь трек за это время.

## Нурхан · P0 · Обучить и измерить резервный SigLIP

Продолжить от готовых 42 кэшей / 40 уникальных видео. На CPU получить бинарные out-of-fold predictions с группировкой точных дублей и известных связанных записей; нормализация и подбор параметров выполняются только внутри train/validation каждого fold. Сравнить с простым baseline и замороженным CV: TP/FP/FN/TN, recall, precision, balanced accuracy, ошибки и покрытие.

Первый результат — диагностический числовой отчёт и небольшой воспроизводимый runner. При неизвестных камерах это только content-group development-оценка: не выдумывать camera IDs, не обходить строгий существующий train/holdout API и не подключать модель к production. Классификатор всего клипа не получает тип нарушения или таймкод из меток. Отрицательный результат тоже полезен, если измерен честно.

Подробные входы, два этапа и критерии приёмки: [team-ml2-next-task.md](team-ml2-next-task.md). PR #43 с pair screening/advisory guards эту задачу не закрывает и не переписывается.

## Алпамыс + Олжас · P0 · Проверить, что действительно видно в восьми пилотных видео

Алпамыс вручную размечает события; Олжас независимо проверяет положительные решения и спорные случаи. Для каждого эпизода указать действие, участника без идентификации личности, предмет, начало/решающий момент/конец и видимость. Допустить «неясно»; пропущенный в кадрах шаг не равен доказанному отсутствию проверки. Отметить, полная это разметка или только первичное событие.

Одновременно заполнить реальные `angle_id` и `source_group`, если они известны. Неизвестные оставить неизвестными. Старые видео остаются development; organiser labels сохранить, спорные уточнения записать отдельно с provenance.

Сдать локальный inventory и adjudication-файл с actual content hashes, reviewer/date и согласованными решениями для дублей. Готово, когда все восемь клипов проверены, разногласия перечислены, вторым человеком проверены все положительные решения, а validator проверяет времена и enum. Видео, кадры и закрытые описания в Git не добавлять.

## Нариман · P1 · Измерить полный запрос и проверить отказ VLM

Подготовить небольшой harness: времена стадий и полного job, оставшийся deadline, фактические model calls, причина fallback, память при доступности измерения. Сначала проверить scripted fixtures; реальный CV + scene + VLM + evidence запускать одним worker после окончания текущих GPU-прогонов и фиксации профиля Агыбая. Discovery по умолчанию остаётся выключенным.

Проверить обычный запрос, недоступную модель, занятый worker, истёкший deadline и ошибку inference. При fallback исходные CV-события сохраняются; внутри job нет скачивания или перезапуска модели. API К1 не менять.

Сдать harness и короткий числовой отчёт: cold startup, warm enhancement и full job отдельно, peak memory либо явное «не измерено». Время probe не выдавать за SLA полного сервиса; scripted tests не подтверждают качество модели.

## Рамазан · P1 · Довести локальный просмотр и ручную проверку evidence

В существующем локальном review обеспечить ответ «недостаточно данных», отображение исходного времени evidence и обратимый экспорт человеческих решений для Алпамыса. Не строить заново evaluator или backend. При отсутствии source metadata ничего не угадывать по confidence; API К1 сохраняется.

Готово, когда missing evidence, ошибка, пустой результат и два разных события с одинаковым округлённым временем отображаются без выдуманных кадров/таймкодов. «Неясно» не превращается в отрицательную метку, а присутствие правовой ссылки не отображается как доказанная достоверность события. Проверка — synthetic fixtures, без публикации приватных кадров.
