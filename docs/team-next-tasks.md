# Ближайшие задачи для команды

Задачи подготовлены для передачи участникам. Внешние сообщения и GitHub Issues не отправлялись. Qwen/MLX и проверку качества типов ведёт Агыбай; повторять этот эксперимент другим участникам не нужно. Новая съёмка в текущем цикле недоступна: задачи используют имеющиеся 40 уникальных development-видео и проверку пригодности внешних данных. Ниже — отдельные результаты, которые можно делать параллельно. Объём первого подхода — ориентировочно 2–4 часа, без обещания закончить весь трек за это время.

## Нурхан · P0 · Закончить matched CV / SigLIP comparison

Этап A уже завершён и слит через [PR #45](https://github.com/AGGIB/datathon26/pull/45): mean-pooled SigLIP дал TP7/FP12/FN14/TN7, balanced accuracy 0,3509 на 40 development contents. Польза не доказана; повторять обучение или подбирать seed по этому результату не нужно. Подробности: [ml-siglip-oof.md](ml-siglip-oof.md).

Следующая поставка — существующие заранее объявленные AND/OR сравнения с настоящими замороженными CV-ответами, без изменения folds/thresholds. На машине Агыбая подготовлен private `var/runs/nurkhan_frozen_cv_af24b8b.json`: producer `af24b8b29b01220cc608726a8d7a60d9f8b8087a`, development_tuned=true, 42 записи / 40 actual SHA, 24 числовых события. Parser принял весь export; типы, времена и confidence совпадают с baseline. На машине Нурхана нужно проверить связь с его настоящим cache manifest и совместимость cohort, не подставлять отсутствующие ответы и не считать текущую parser-проверку полным cache audit.

Готово, когда получен отчёт matched coverage, TP/FP/FN/TN, lost CV TP и new FP для CV/SigLIP/AND/OR на том же наборе с сохранённым provenance. При отсутствии локального private export запросить файл у владельца; агрегаты не превращать в выдуманные predictions. Новых production weights, типов и таймкодов binary head не создаёт. Независимые камеры по-прежнему требуют human metadata и новых данных. Исходный протокол этапов сохранён в [team-ml2-next-task.md](team-ml2-next-task.md); PR #43 также уже слит.

## Алпамыс + Олжас · P0 · Проверить, что действительно видно в восьми пилотных видео

Алпамыс вручную размечает события; Олжас независимо проверяет положительные решения и спорные случаи. Для каждого эпизода указать действие, участника без идентификации личности, предмет, начало/решающий момент/конец и видимость. Допустить «неясно»; пропущенный в кадрах шаг не равен доказанному отсутствию проверки. Отметить, полная это разметка или только первичное событие.

Одновременно заполнить реальные `angle_id` и `source_group`, если они известны. Неизвестные оставить неизвестными. Старые видео остаются development; organiser labels сохранить, спорные уточнения записать отдельно с provenance.

Сдать локальный inventory и adjudication-файл с actual content hashes, reviewer/date и согласованными решениями для дублей. Готово, когда все восемь клипов проверены, разногласия перечислены, вторым человеком проверены все положительные решения, а validator проверяет времена и enum. Видео, кадры и закрытые описания в Git не добавлять.

Дополнение после исследования: для заранее выбранных типов полностью просмотреть выбранные интервалы и добавить matched hard negatives (ключ/блик или ручка; одежда/сумка; питьё/касание лица). Хранить start/decisive peak/end, observed/unknown и actor/object continuity. Human primary-only labels не считать полным перечнем эпизодов. Один источник и все его нарезки целиком остаются в одном split; protected holdout не используется для prompt/threshold tuning.

Конкретный MVP без новой съёмки: [event gold на существующих видео](vlm-data-without-recording.md), сначала 8 уникальных источников и 24 записи покрытия, затем весь набор. Counts эпизодов определяются просмотром, а не квотой.

Для работы готов [CLI и формат разметки](frontier-human-review.md): на всех 40 содержимых создаются 120 пар «видео × тип», отдельные ответы двух проверяющих и adjudication. Начальные строки остаются `unreviewed`; инструмент не заполняет решения за людей. Каждый проверяющий отдельно отмечает положительные эпизоды, контрасты и неизвестность.

Отдельный ближайший разбор — двери: проверить переходы открыто/закрыто, видимость двери и состояние на исходном reference-кадре. Это нужно для трёх оставшихся ложных тревог. Текущий трёхтиповый scaffold дверь не покрывает; наблюдения по двери вести отдельным overlay с reviewer/date, временами и кодами неизвестности, сохраняя исходные метки. Простое исключение перекрытых кадров уже потеряло правильное попадание по времени и отклонено; [результат диагностики](cv-precision-invariants.md) не является готовым исправлением.

## Нариман · P1 · Измерить полный запрос и проверить отказ VLM

Подготовить небольшой harness: времена стадий и полного job, оставшийся deadline, фактические model calls, причина fallback, память при доступности измерения. Сначала проверить scripted fixtures; реальный CV + scene + VLM + evidence запускать одним worker после окончания текущих GPU-прогонов и фиксации профиля Агыбая. Discovery по умолчанию остаётся выключенным.

Проверить обычный запрос, недоступную модель, занятый worker, истёкший deadline и ошибку inference. При fallback исходные CV-события сохраняются; внутри job нет скачивания или перезапуска модели. API К1 не менять.

Сдать harness и короткий числовой отчёт: cold startup, warm enhancement и full job отдельно, peak memory либо явное «не измерено». Время probe не выдавать за SLA полного сервиса; scripted tests не подтверждают качество модели.

Новый отдельный deliverable: manifest `requested_cv_time → decoded source_frame_index → actual PTS` с origin/timebase и привязкой того же кадра к evidence JPEG. Проверить synthetic CFR/VFR/start-offset/repeated-PTS; не переименовывать нынешний `Frame(t,t)` в настоящие PTS. Критерий — однозначный round-trip кадра и проверенный перевод в video-relative time, без дрейфа или механического переименования GT timebase.

## Алпамыс + Олжас · P1 · Выбрать пригодный внешний object/contact контроль

Сдать 3–5 source cards: official URL/revision, лицензия именно данных, происхождение и доступные hand/object/contact/temporal labels. Отдельно показать покрытие banknotes/papers, coat/bag, resolved key/lock, stamp/book; отсутствующие классы не выдумывать. Выбрать один небольшой разрешённый subset, проверить отсутствие пересечения с holdout и до эксперимента зафиксировать physical predicate и hard negatives. Сначала metadata/curation на CPU, без новой большой модели. Generic hand/action dataset сам по себе не доказывает различимость мелкого предмета на нашей камере.

## Рамазан · P1 · Довести локальный просмотр и ручную проверку evidence

В существующем локальном review обеспечить ответ «недостаточно данных», отображение исходного времени evidence и обратимый экспорт человеческих решений для Алпамыса. Не строить заново evaluator или backend. При отсутствии source metadata ничего не угадывать по confidence; API К1 сохраняется.

Готово, когда missing evidence, ошибка, пустой результат и два разных события с одинаковым округлённым временем отображаются без выдуманных кадров/таймкодов. «Неясно» не превращается в отрицательную метку, а присутствие правовой ссылки не отображается как доказанная достоверность события. Проверка — synthetic fixtures, без публикации приватных кадров.

## Порядок

Нурхан завершает matched comparison, Алпамыс и Олжас — ручную разметку существующих эпизодов. Нариман и Рамазан могут готовить инструменты параллельно. Нарезки и crops остаются в группах своих исходников и не увеличивают число независимых записей. Проверка нового ракурса сейчас не выполнена и не подменяется этими пилотами. Более длинный исследовательский backlog: [vlm-next-tasks.md](vlm-next-tasks.md).
