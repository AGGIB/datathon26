# Внешняя выборка для #23

По последнему уточнению пользователя собираются **10–15 сторонних клипов только с банковскими сценами под наши типы**. Подготовка ведётся отдельно от PR32 в ветке `codex/external23-bank-intake`, основанной на нормативной правке `fbeae60` (PR32). Скачивание, технический импорт, разметка действий и проверка правового контекста — разные этапы. Наличие файла или подписи модели не завершает #23. QA #25 отложен до готовности API.

Получены и технически проверены три банковских исходника из трёх групп: CareerOneStop Tellers, NARA NAID 12089 и RBS TCR training. Происхождение, ограничения прав и стабильные страницы собраны в [реестре источников](external23-sources.md). Разные планы одного фильма сохраняют его `source_group`. Человеческой проверки событий и gold-меток пока нет. Девять Commons-кандидатов сохранены как `reserve` с причиной `bank_context_not_confirmed`; опубликованные SHA1 / размеры совпали, SHA256 и `ffprobe` записаны. Два из них короче 5 секунд, длительность не менялась. Retail MEVA не скачивается и в #23 не засчитывается.

## Локальные файлы и запуск

Весь материал находится в игнорируемом `data/external23/`: исходники `sources/`, клипы `clips/`, подтверждения прав `rights/`, manifest, `intake.json`, `annotations.json`, сырые ответы модели и локальная страница проверки. В Git включаются только инструменты и документация. Кадры, видео, частные наблюдения и ответы модели не выводятся в облачный чат, не открываются через чат и не отправляются в GitHub.

Нужны Python 3.10+ из-за `Path.is_relative_to` / аннотаций типов и локальные `ffprobe` / `ffmpeg` (по умолчанию `/opt/homebrew/bin/`). Основной импорт использует стандартную библиотеку Python, без ML-зависимостей.

```sh
# Только для нового пустого каталога, не поверх полученного manifest:
python3 -B tools/external23_intake.py init

python3 -B tools/external23_intake.py validate
# Для незавершённого пула кандидатов явно добавить --allow-partial.
python3 -B tools/external23_intake.py import --download
python3 -B tools/external23_intake.py check-annotations
python3 -B tools/external23_review.py
```

Без `--download` импорт использует только уже локальные файлы. По умолчанию на исходник установлен предел 2048 MiB, при загрузке сохраняется не менее 1 GiB свободного места. `--max-source-mib` меняет этот технический предел. Файлы и заполненная разметка не перезаписываются; повторный импорт проверяет хеши. Manifest можно расширять новыми источниками / клипами, сохраняя прежние записи; историю SHA256 manifest сохраняет intake. Для замены существующего клипа нужен новый ID.

## Manifest и происхождение

`init` создаёт только пустой manifest `schema_version: 1` с `sources: []` и `clips: []`, без фиктивных данных. Обычная проверка ожидает 10–15 выбранных клипов. Пул может содержать дополнительные `reserve` / `candidate` (до 50 всего); `--allow-partial` допускает незавершённый отбор. Поле `selection` у клипа явно отличает выбранные клипы от резерва, `split` допускает только `external_holdout`. Резерв не засчитывается в выполненный набор и не используется для обучения.

| Поле источника | Что должно быть установлено |
| --- | --- |
| `id` | Уникальный безопасный локальный ID |
| `source_url` / `source_page_url` | Прямой публичный HTTPS URL и страница происхождения |
| `license.id` / `license.url` | Точная лицензия, без замены отдельного LicenseRef на CC BY |
| `attribution` | Автор / требуемая атрибуция из подтверждённых метаданных |
| `source_group` / `camera_id` | Общая сцена / событие и камера; неизвестная камера остаётся `unknown` |
| `source_context.country` / `scene_type` | Подтверждённая страна / назначение; неизвестные сведения остаются `null` / `unknown` |
| `expected_sha1` / `expected_sha256` | Опубликованный контрольный хеш, если доступен; отсутствие не означает проверку эталона |
| `expected_size_bytes` | Опубликованный размер, если доступен |
| `rights_proof.path` / `sha256` | Локальные метаданные, подтверждающие происхождение и лицензию |
| `local_path` | Необязательный путь уже скачанного исходника внутри приватного каталога |

Каждый элемент `clips` содержит `id`, `source_id`, `start_sec`, `end_sec`. Два `null` означают весь исходник: начало 0 и конец берутся из измеренной длительности, а не из разметки события. Указанные числовые границы относятся к секундам воспроизведения исходника. Инструмент перекодирует только видео, удаляет звук и свободные media tags. Длительности коротких исходников сохраняются; `temporal_criteria_note: shorter_than_5_seconds` отмечает ограничение временных критериев.

Для `selection: selected` обязательны фактический `source_context.scene_type: bank_cashdesk` и `source_context.evidence_reference` — ссылка на подтверждение банковской сцены. Фактическая страна может оставаться неизвестной или быть другой: фильтр относится к банковскому контексту, а не к съёмке непременно в Казахстане. Неподтверждённые кандидаты остаются `candidate` / `reserve`; `selection_reason` фиксирует причину. Сценарное допущение не заменяет этот обязательный фильтр #23.

`intake.json` содержит SHA256 исходника и клипа, проверенный опубликованный SHA1 при наличии, размер / лицензию / атрибуцию, source offsets и разрешённые технические поля `ffprobe`. Свободные теги и stderr медиадекодеров не печатаются. Условие разбиения будущей выборки — `source_group`: разные камеры одного события нельзя разносить между обучением и проверкой лишь из-за разных файлов или SHA256.

## Разметка действий и правовой контекст

Импорт создаёт пустые записи `pending_review`, `events: []`, `legal_gold: null`. Пустой список не является меткой `no_violation`.

| `provenance` события | Необходимое происхождение |
| --- | --- |
| `source_human` | Ссылка на опубликованную исходную разметку и её исходный интервал. Это не наша ручная проверка. |
| `local_model` | Локальная модель, точная версия / revision и ссылка на сырой локальный результат. Это черновик. |
| `reviewed_human` | Реальный проверяющий и дата проверки, а также ссылка на проверяемый материал |

У события заданы `t_start` / `t_end` в секундах **клипа**, `action_label`, список `roles` и `origin`. Элемент роли содержит `role` и `status` из `unknown` / `source_asserted` / `human_reviewed`; внешний вид сам по себе не устанавливает должность. Для source-human интервала указываются единицы `seconds` либо `frames`; FPS берётся из документации разметки, не угадывается по среднему FPS. Валидатор сверяет перевод исходного интервала в локальные секунды с учётом обрезки клипа.

Gold-метка требует настоящей ручной проверки: статус `reviewed_human`, проверяющий и дата, подтверждённая банковская сцена, роли, условия нормы и ссылки на подтверждения. Фактическая страна съёмки не обязана быть Казахстаном для теста индикаторов по нормативной схеме РК; поле `applicability.jurisdiction: KZ` задаёт эту схему и не переписывает фактическую страну. Магазин или передача предмета не заменяют установленный банковский контекст. Сценарное допущение не позволяет обойти этот фильтр. При непроверенных условиях сохраняются действия / кандидаты и `legal_gold: null`. Валидатор проверяет полноту записи, а не истинность утверждений. Автоматические подписи и импорт действий остаются черновиками, пока не проверены человеком.

`pending_review` — статус разметки, не третий API-вердикт. Единственные возможные правовые вердикты остаются `violation` / `no_violation`; отсутствие нормы или непроверенный контекст автоматически не превращаются в отрицательную метку.

## Локальная проверка человеком

`tools/external23_review.py` создаёт приватную HTML-страницу с локальными видеоплеерами, переходом к введённому времени и редактором JSON. При наличии сырых ответов модели их можно подключить через `--model-results`. Страница работает без внешних скриптов, сети и autoplay; её открывают вручную на своём компьютере, без облачного просмотра или скриншотов в чате. После редактирования JSON скачивается локально, помещается в `data/external23/annotations.json` и проверяется командой `check-annotations`.

## Необязательный локальный VLM

В отдельном окружении `/private/tmp/datathon26-external23-mlx` установлены MLX-VLM 0.7.8 и MLX 0.32.4. Минимальная зависимость зафиксирована в `tools/requirements-external23-vlm.txt`, полный фактический lock — в приватном `data/external23/runtime/requirements-vlm.lock.txt`. Основной intake этого окружения не требует.

Первоначальный runner использует `mlx-community/SmolVLM2-500M-Video-Instruct-mlx`, Apache-2.0, pinned revision `fa57db46815177fbdfd65cc85a2b3416a8332268`. Локальные файлы занимают около 1.02 GB; SHA256 `model.safetensors` совпал с upstream LFS. Модель хранится в `data/external23/models/smolvlm2-500m-video/` вместе с download manifest. 7B-модель не скачивалась: на M1 с 8 GB RAM она не оставляла достаточного рекомендованного запаса памяти.

`tools/external23_vlm.py` принимает приватный JSON `items` с `clip_id`, локальным `video_path`, измеренной `duration_seconds`, `source_reference` (либо с уже локальными `frames`). Он выбирает до 8 кадров не более 384 px, максимум 128 новых токенов, устанавливает `HF_HUB_OFFLINE=1` / `TRANSFORMERS_OFFLINE=1`, `local_files_only=True`, `trust_remote_code=False` и загружает только локальную модель. Сырые ответы и логи пишутся в приватные файлы; stdout содержит только счётчики, состояние и latency. Время равномерного семплирования не является временем обнаруженного события.

Технический offline smoke Smol на одном Commons-кандидате прошёл; batch остановлен после банковского уточнения. Эти материалы остаются резервом. На банковских планах Smol не дал пригодного структурированного результата, поэтому дальнейшие повторы прекращены.

Для ограниченного банковского screening локально использована `mlx-community/Qwen3.5-2B-4bit`, Apache-2.0, revision `674aaa7240b91e8012fcad5d791b7dfe5ba90207`. Snapshot около 1,75 GB, SHA256 `model.safetensors`: `713fe7e5d3c3965f7106b0d0ee17615f7869c23c8d327996df8c1196fbcf07d5`. Файлы и download manifest находятся в приватном `models/qwen35-2b-4bit/`. Используются встроенная архитектура MLX-VLM, локальные пути, offline-флаги и `trust_remote_code=False`, non-thinking режим, лимит памяти 80% рекомендованного рабочего набора и cache 256 MiB. Работает один процесс модели.

Smoke с одним / двумя кадрами и максимумом 512 токенов дал 2 корректных JSON-ответа за 23,3 секунды. Первый screening 46 планов из трёх групп завершился за 479,6 секунды; все ответы прошли форму JSON. Из-за двух слишком широких английских пояснений эти результаты сохранены только как предложения сцен, без принятых типов.

Пояснения исправлены по текущему русскому каталогу. Второй проход ограничен полными критериями статических слабых индикаторов Т15, Т17 и Д13 и четырьмя кадрами на план. Неподтверждённый основной визуальный признак требует пустого результата; его нельзя переносить в неподтверждённый правовой контекст. Временные типы, отсутствие действия и полный цикл операции по разреженным кадрам не принимаются. Любой сохранённый кандидат остаётся `local_model / pending_review`, `legal_gold: null`. Второй проход 30 сцен завершился за 247,6 секунды; **0 из 30 ответов прошли схему**, принято **0** типов. Отклонения связаны с формой JSON, картами условий и отсутствием требуемой видимой опоры. JSON-схема проверяет форму, а не истинность наблюдения.

Два синтетических negative control (однотонный и детерминированный шум) проверены тем же полным prompt, на той же модели и с прежним ограничением памяти: ожидаемый пустой ответ прошёл **0 из 2**. Модель предложила непустые списки типов без требуемой видимой опоры. Контроли не являются видео и не входят в выборку. Автоматический отбор остановлен; дополнительных моделей и повторов не планируется в этом проходе.

Приватная страница `data/external23/review/banking-screen-review.html` содержит три банковских исходника, технические границы планов и явно отклонённые сырые ответы. Её открывают только локально, не через облачный просмотр. `annotations.draft.csv` содержит ровно девять согласованных колонок и пока только заголовок: положительных строк 0, выбранных клипов 0, ручных проверок 0, gold-меток 0. Требование #23 о 10–15 пригодных клипах **не выполнено**. Для продолжения нужна фактическая локальная проверка человеком; отрицательные метки из неудачи модели не создаются.

Времена семплов и границы плана не являются локализованным событием или его длительностью. Для черновика они могут задавать только явно приблизительное окно поиска; `t_peak` без локализации остаётся пустым. Реестры, сырые ответы, отдельные prompts / хеши и CSV находятся только в приватном `data/external23/`. Число пригодных клипов не доводится до 10–15 искусственно.

Импорт официальных аннотаций будущего подходящего источника потребует явного преобразования его схемы и временной шкалы. Импорт не выдумывает такую разметку и не считает технический intake выполненной проверкой событий. Синтетические проверки инструмента: `python3 -B tools/check_external23_intake.py`; они не читают реальные видеоданные и не выполняют загрузки.
