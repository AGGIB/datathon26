## Приватность и текущее состояние

Видео, кадры, наблюдения, заполненные метки и модельные ответы остаются под игнорируемым `data/external23/`. Они не включаются в Git, облачный чат или скриншоты. `data/open` для этих инструментов не нужен. Тесты используют временные синтетические фикстуры, мок сети и процессов.

Все прежние 39 записей, исходные ID, SHA256, offsets и история сохранены в metadata-only архиве `excluded/pr34-kz-rights-scope/`. Каталоги 12 исходников, 39 клипов и 9 рабочих каталогов с 268 кадрами обратимо перенесены через filesystem rename в `excluded/pr34-kz-rights-scope/media/`; активные `sources/` и `clips/` пусты. Содержимое медиа при этом не читалось, не декодировалось и не хешировалось. `relocation-map.json` сохраняет старые / новые относительные пути и счётчики; исходные ID, SHA256 и offsets не переписывались. Веса моделей оставлены на месте в отключённом состоянии. NARA / RBS исключены из-за неподтверждённых прав, CareerOneStop — по географии; Commons не подтверждают требуемый банковский контекст. Старые HTML-страницы архивированы; обычные entrypoints показывают пустую очередь без медиаплееров. Подробнее — [реестр происхождения](external23-sources.md).

Исторические ID не мигрируют переименованием файлов. Новый clip ID обязан начинаться с `ext23-`; это защищает от коллизий с организаторскими `X-12` / `Х-12`. Повторный импорт проверяет SHA256 содержимого. Устаревшие записи допустимы только в исключённом архиве.

## Проверка manifest и прав

```sh
# init — только для нового пустого каталога
python3 -B tools/external23_intake.py init
python3 -B tools/external23_intake.py validate --allow-partial
python3 -B tools/external23_intake.py check-annotations
```

Нормальная проверка завершённого manifest требует 10–15 `selected`, максимум 50 записей всего и минимум двух независимых `source_group`. `selection_policy.min_source_groups` может повысить минимум, но не снизить его ниже двух. `--allow-partial` допускает незавершённый пул; один источник не становится независимыми источниками после нарезки.

| Поле | Требование |
| --- | --- |
| `source_url`, `source_page_url` | Публичные HTTPS-страницы происхождения без логина / обходов |
| `license.id`, `license.url` | Точная пара из whitelist ниже; свободный текст и похожие имена не принимаются |
| `source_context.country` | Фактическая страна; `KZ` обязательна для загрузки и материализации кандидатов / selected |
| `source_group`, `camera_id` | Исходная группа и установленная камера; неизвестное значение сохраняется неизвестным |
| `start_sec`, `end_sec` | Исходные offsets; либо оба `null` для полного источника; содержимое / offsets неизменяемы |
| `selection` | `candidate`, `reserve`, `selected`; reserve — только метаданные без чтения / загрузки / нарезки |
| `bank_scene_confirmed`, `bank_scene_evidence_reference` | Для selected подтверждаются на уровне конкретного клипа, а не всего фильма |
| `angle_id`, `camera_id` клипа | Для selected обязательны структурированные ASCII ID `[A-Za-z0-9][A-Za-z0-9_.:-]{0,79}` без пробелов по краям и префиксов формул; unknown / unassigned / неизвестно не проходят |
| `rights_proof.path`, `sha256`, `url` | Для любого материализуемого candidate / selected обязательны локальное доказательство, его SHA256 и HTTPS-страница прав до ffprobe / нарезки; selected требует proof непосредственно у клипа, candidate может ссылаться на proof источника |

Whitelist:

| ID | Точная страница |
| --- | --- |
| `CC0-1.0` | https://creativecommons.org/publicdomain/zero/1.0/ |
| `CC-BY-4.0` | https://creativecommons.org/licenses/by/4.0/ |
| `PDM-1.0` | https://creativecommons.org/publicdomain/mark/1.0/ |
| `PD-US-GOV` | https://www.copyright.gov/title17/92chap1.html#105 |

Reserve / excluded могут оставаться только метаданными без proof и без чтения медиа. Для Public Domain одного государственного хостинга недостаточно: `rights_proof.url` указывает на источник подтверждения прав именно материала. Проверка кода подтверждает форму декларации, путь и хеш доказательства; фактическую лицензию и применимость подтверждает человек. `LicenseRef-*RightsUnconfirmed`, `Undetermined`, private_evaluation_only, CC BY-SA и AttributionOnly не превращаются в разрешённую лицензию.

`--download` возможен только для whitelisted KZ-источника с собственным проверенным `rights_proof`. HTTPS→HTTP / FTP redirect отклоняется до запроса следующего адреса. Без `--download` сеть не используется. Бинарники `ffmpeg` / `ffprobe` берутся из PATH; `--ffmpeg` / `--ffprobe` задают явные переопределения. Лимит исходника по умолчанию 2048 MiB, запас диска 1 GiB.

```sh
# Только после отдельного решения о новом допустимом manifest:
python3 -B tools/external23_intake.py import --allow-partial --ffmpeg ffmpeg --ffprobe ffprobe
# --download добавляется явно; в текущем scope новые загрузки остановлены.
```

FFmpeg создаёт клип без аудио и исходных описательных тегов, с двумя потоками декодирования / кодирования и одним filter thread. Запись идёт в уникальный временный файл с atomic replace. До экспорта клипа сохраняется pending identity; при сбое между готовым клипом и intake прежний orphan сохраняется отдельно, затем безопасно пересоздаётся. Неизвестный orphan без подтверждённой identity не принимается.

## Изменения контекста и ручная разметка

`source_context` может уточняться без смены source ID. Для этого manifest содержит append-only `change_log`: `entity` (`sources` / `clips`), `id`, `field`, `before_sha256`, `after_sha256` (канонический JSON value hash), `changed_by`, ISO `changed_at`, `reason`. Предыдущие записи журнала сохраняются. Каждое новое изменение подтверждается новой записью в добавленном суффиксе: старую запись перехода A→B нельзя переиспользовать после B→A. Аналогично журналируются изменения прав, угла и подтверждения банковской сцены у существующего клипа. Источник, SHA / ожидаемые хеши и offsets менять нельзя. Intake хранит журнал переходов manifest; метаданные обновляются без повторной загрузки существующего файла.

`annotations.json` содержит `pending_review` черновики с пустыми events и `legal_gold: null`. Происхождение события: `source_human`, `local_model` либо фактически `reviewed_human` с именем и датой. Публикация shotlist / технические границы планов не являются визуальной разметкой события. Модельные и отклонённые результаты не становятся отрицательными метками.

Для gold нужны `selection: selected`, известные angle / camera, подтверждённые права и сцена, `reviewed_human`, `full_clip_reviewed: true`, установленные роли / условия и ссылки evidence. Фактическая страна хранится в `source_context.country`, нормативная схема отдельно — `normative_scenario` с `jurisdiction: KZ`, `basis: indicator_benchmark`, `decision_reference`. Это условная оценка по принятому каталогу, не обвинение реальных людей. `simulation_context` не заменяет фактический географический и банковский фильтр.

Положительные события используют стабильный runtime `type_id` из текущих 27 активных ID, локальные `t_start`, `t_end`, обязательный `t_peak`, наблюдение и provenance ручной проверки. Смешанные ракурсы и дубликаты `(type_id, t_peak)` отклоняются. Т04 остаётся допустимым активным индикатором без rule; отсутствие нормы не превращает его в отрицательную метку. Отрицательная метка допустима только после фактической проверки полного клипа человеком, с пустыми events / type_ids.

```sh
python3 -B tools/external23_review.py --output data/external23/review/index.html
python3 -B tools/external23_intake.py check-annotations
```

Страница локальная: CSP блокирует сеть, autoplay отсутствует, текст экранирован. Через облачный чат её не открывают. Скачиваемый `review-subset.annotations.json` содержит только показанные клипы: его сохраняют отдельно, объединяют с общим JSON по `clip_id` и проверяют полный файл. Пути `excluded/` / `quarantine/` не являются входом обычного review / экспорта.

## Мост к форматам команды

```sh
python3 -B tools/external23_export.py
```

Экспортируются только selected + reviewed_human + gold. Pending, отклонённые ответы и техническая очередь пропускаются без отрицательных меток. Проверяются whitelisted права / KZ / угол, SHA256 именно экспортируемого клипа, namespace, нормализованные video ID, дубли хешей и минимум независимых групп.

* `annotations.csv`: ровно `video,type_id,t_start,t_end,t_peak,actor,what_visible,angle_id,comment`. Runtime ID сохраняются. Для проверенного отрицательного клипа — одна строка `type_id=none`, все времена пусты.
* `labels.csv`: `video,timestamp,label,content_sha256`; `label` — `нарушение` / `без нарушения`. У положительного клипа timestamp — самый ранний проверенный локальный t_peak, у отрицательного — пусто.
* `external_holdout.json`: `items` с `video_id`, `angle_id`, `content_sha256`, `source_group`, `split=external_holdout`. Это manifest для последующего объединения, **не готовый evaluator split.json**.

PR30 требует непустой train, полное взаимно-однозначное покрытие labels и разбиение без пересечений angle / content hash. Этот инструмент не создаёт фиктивный train и не импортирует неслитый код PR30. `--split-json` явно отклоняется до записи файлов: готовый split требует проверенных базовых train labels / split и отдельного строгого объединения с evaluator. Неизвестный ракурс не проходит даже external holdout export.
