# Офлайн-проверка VLM на пяти парах

## Назначение и протокол

`python -m ml.vlm.pair_eval` — отдельный локальный эксперимент, не часть
`ml.pipeline`. Проверяются ровно пять пар из решения владельца PR #30:
X-2/X-3, X-13/X-14, X-16/X-17, X-34/X-35, X-43/X-44. Одиночный X-1 не
включён: отрицательная пара для него не задана. Это выбранная открытая выборка,
не независимый holdout и не оценка детектора.

- В каждой паре должна быть одна положительная и одна отрицательная метка.
  Ориентация пары определяется из меток, а не из порядка идентификаторов.
- Целевой тип берётся из положительной аннотации, описание — из каталога типов.
  Обоим членам пары передаётся **один и тот же prompt**. Файловые имена,
  метки, партнёр пары, аннотированные timestamps и описания конкретных сцен
  в prompt не включаются. Тип известен заранее: эксперимент проверяет
  подтверждение заданного условия, не открытое обнаружение любых нарушений.
- Независимо от меток выбираются три кадра около 10%, 50% и 90% длительности.
  Это CV index/FPS timeline, не container PTS. `OwnerFrames` получает кадры
  одним вызовом `ml.video.frames_at` на видео в killable-процессе.
- Один model worker подготавливается до первого видео. Совместный бюджет
  probe/extract/infer задаётся явно на каждое видео; `max_new_tokens=128`.
- Ответ должен быть строгим JSON с ровно двумя boolean-полями:
  `violation` и `insufficient_evidence`. Целые 0/1, лишние ключи, Markdown,
  обрезанный ответ и свободный текст не исправляются постфактум.
- Пара правильна, только если **оба** ответа валидны, достаточны и правильны.
  Знаменатель всегда пять пар / десять видео. Missing, uncertain, invalid,
  timeout и ошибки остаются в знаменателе; это не чистые отрицательные ответы.

## Воспроизведение

Подготовить зависимости `requirements-ml-vlm.txt` и `ml/requirements.txt`,
разрешённые локальные веса и закрытые входы заранее. Никаких облачных GPU/API.
Запускать на собственной физической машине из корня репозитория:

```bash
python -m ml.vlm.pair_eval \
  --labels '<open_labels.xlsx>' \
  --videos-dir '<videos>' \
  --annotations kb/annotations.csv \
  --model-path models/smolvlm-256m-instruct \
  --model-id 'HuggingFaceTB/SmolVLM-256M-Instruct@7e3e67edbbed1bf9888184d9df282b700a323964' \
  --output artifacts/vlm-pairs-new-run \
  --budget-sec 180 --startup-timeout 120 --device cpu
```

`--output` — **новый** каталог внутри игнорируемого `artifacts/`.
Каталог резервируется до чтения/хеширования входов. `report.json` атомарно
обновляется после каждого видео; готовый префикс переживает прерывание.
Повторное использование каталога запрещено; автоматического resume нет.

Отчёт содержит локальные prompts, исходные ответы, SHA256 входов, выбранные
времена/размеры кадров и раздельные времена probe, extract, inference и полного
прохода. Он приватный: не добавлять в Git, не публиковать и не отправлять ИИ.
Временные PNG удаляются после вызова. Stdout содержит только агрегированные
счётчики и времена; сообщения сторонних библиотек подавлены. Python audit
hook запрещает исходящие сокеты в CLI и spawned workers до импорта модели;
это не OS sandbox для произвольного нативного кода.

Exit 0: десять пригодных ответов (не обязательно правильных); exit 2: есть
непригодные ответы либо ошибка входов; exit 130: прерывание.

## Локальный результат: SmolVLM-256M, 2026-10-17

Выполнена настоящая pretrained generation на всех десяти видео, не scripted
backend. Профиль: CPU, Python 3.10.0, Torch 2.13.0, Transformers 4.57.6,
Pillow 11.2.1, OpenCV headless 4.11.0.86, greedy decoding, максимум 128 новых
токенов. Исходные кадры **464 × 848**, по три на видео: всего 30 кадров.

Checkpoint и SHA256 весов указаны в [лицензиях](licenses-ml.md).
Процессор использует локальный профиль `size.longest_edge=512`,
`do_image_splitting=true`; веса не менялись. SHA256 `preprocessor_config.json`:
`cfdb343d0fdc216d8fd0619de54f053785716a0ae88ff7e4a867074401f79d09`.

## Решение и ограничения

Польза **этого профиля SmolVLM-256M не показана**: подключать его к pipeline
по этим данным нельзя. VLM не подключена; confidence/observation и набор
кандидатов правил не меняются. Эти результаты не доказывают, что все варианты
SmolVLM бесполезны: формат ответа, язык описания типа и редкая выборка кадров
ограничивают эксперимент; трёх кадров может не хватить для процедуры.
Изменение prompt, разрешения или sampling требует нового явного прогона,
а не ручной переинтерпретации невалидных ответов.

Qwen3-VL-4B разрешена и закреплена в манифесте, но здесь не запускалась.
Qwen2.5-VL-7B/32B тоже не измерялись. Их CPU-латентность, пригодность ответов и
сравнение качества остаются неизвестными; переносить на них эти времена нельзя.
Ни SLA production К2, ни независимое качество CV/baseline этим экспериментом
не подтверждены.
