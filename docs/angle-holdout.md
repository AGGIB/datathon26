# Независимый ракурс: данные и проверка

На 17.10.2026 в локальном `open/videos/` доступны 42 файла организаторов, 40 уникальных SHA256. Этот набор уже использовался для разработки правил и калибровки порогов. Его нельзя объявлять новым тестом после переименования, изменения перспективы или назначения новых angle IDs. В текущем `kb/annotations.csv` ракурс не указан ни у одной из 42 строк; это не означает, что физический ракурс у всех одинаковый.

Новую съёмку пользователь провести не может. В [PR Олжаса #50](https://github.com/AGGIB/datathon26/pull/50) найден каталог 14 публичных видеоссылок общей длительностью 73:25. На проверенном commit `da7eacd528631bfafe4d6adfa424c6584a4a8936` это `discovery_only`: принято / скачано / размечено **0 / 0 / 0**; пригодные непрерывные сцены, ракурсы и независимость исходников ещё не подтверждены. Список служит основой отбора, но пока не даёт нового измеренного ракурса. Исторические материалы external23 исключены из активного набора. Статус оценки — **blocked / нет проверенного размеченного holdout**, а не нулевая или синтетическая метрика.

## Подготовка

`ml.tools.angle_holdout` не декодирует медиа, не запускает модель и не передаёт данные в сеть. Сначала фиксируется весь ранее использованный набор, включая дубликаты:

```bash
python -m ml.tools.angle_holdout freeze-development \
  --videos-dir data/open/videos --labels data/open/open_labels.xlsx \
  --annotations kb/annotations.csv --output var/angle_eval/development.json
python -m ml.tools.angle_holdout prepare \
  --development var/angle_eval/development.json --output var/angle_eval/readiness.json
```

Без `--holdout` в readiness сохраняется `new_angle_manifest_missing`, exit 1; метрики не рассчитываются. Ракурсы и группы исходных записей не угадываются. Человек должен добавить реальные `angle_id` и `source_group` в development manifest. Один `source_group` объединяет фрагменты одной исходной съёмки, включая перекодированные и обрезанные варианты.

Новый локальный manifest использует `schema_version: 1`, список `records` и поля `annotation_origin: "human"`, `reviewed_by`, `reviewed_at` (ISO-дата), `events_exhaustive: true`. Каждая запись содержит:

- `video_id`, абсолютный локальный `path`, настоящий `content_sha256`;
- явные `angle_id` и `source_group`, отличающиеся от development;
- `origin: "locally_recorded"`, `rights_confirmed: true` — декларация владельца съёмки; либо проверенное внешнее происхождение, описанное ниже;
- бинарный `label` 0/1; для положительной записи — все события `events: [{"type_id": "<runtime ID>", "t_peak": 12.4}]`.

Поля происхождения и права подтверждает человек; инструмент не проверяет их юридическую истинность или содержимое кадров. Машинные предложения и первичный тип из старого авторского анализа не заменяют исчерпывающую human-разметку. Внешние кандидаты, proxy-сцены и синтетическая перспектива не объявляются собственной новой съёмкой; пути `excluded`/`quarantine` запрещены.

Для законно лицензированного внешнего видео допустим отдельный `origin: "external_licensed"`. Нужны точные `license_id` / `license_url` из явного allowlist CC0-1.0, CC-BY-4.0, CC-BY-3.0, PDM-1.0; `source_url` первоисточника HTTPS; `attribution`; `rights_confirmed: true`, `rights_reviewed_by`, `rights_reviewed_at`; локальный непустой `rights_proof_path` с настоящим `rights_proof_sha256`. Человек отдельно подтверждает `source_context: {"country": "KZ", "scene_type": "bank_cashdesk"}` (также разрешены bank_vault/bank_incassation) и `bank_scene_confirmed: true`. Одного флага или публичной ссылки недостаточно. Эта ограниченная политика не утверждает, что другие лицензии незаконны: иные условия требуют отдельного review, а не молчаливого принятия. Все остальные барьеры по human-разметке, ракурсам, группам и хешам остаются обязательными.

```bash
python -m ml.tools.angle_holdout prepare --development var/angle_eval/development.json \
  --holdout var/angle_eval/new.json --output var/angle_eval/prepared.json
python -m ml.tools.angle_holdout score --prepared var/angle_eval/prepared.json \
  --predictions var/angle_eval/predictions.json --output var/angle_eval/report.json
```

Predictions соответствуют формату `ml.eval`: список записей с `video_id`, `status`, `verdict`, `violations`, необязательным `elapsed_sec`. Это сохранённые реальные ответы; score сам не запускает inference.

## Защита от утечки и метрики

Prepare сверяет SHA256 с реальными байтами, запрещает пересечение exact-content, camera IDs и source-recording групп между development и test. В каждой группе дубликатов должны совпадать бинарные метки, ракурс и полный список событий. При score файлы хешируются снова. Эти проверки не обнаруживают незаявленную связь перекодированных источников; для неё нужна достоверная human-provenance.

До просмотра test-ответов фиксируются код, модель, prompt, пороги и допуск времени. Для дальнейшей настройки нужна отдельная validation-съёмка; после настройки на test он становится development, а для нового заключения требуется следующий независимый test.

Отчёт использует `ml.eval` и считает качество по уникальным content groups, сохраняя диагностику отдельных файлов. Отсутствующие, ошибочные и просроченные ответы не становятся чистыми отрицательными. Для каждого явно заданного ракурса отдельно показаны бинарные исходы, end-to-end **precision / recall / F1**, доля правильных ответов по всем группам, число пропусков/ошибок и три независимых результата:

- совпадение типа без требования времени;
- взаимно-однозначное совпадение времени без требования типа;
- взаимно-однозначное совпадение **того же типа и времени** в допуске ±2 с, с event precision/recall.

Только последняя метрика подтверждает правильные тип и таймкод одного события. Лишние события уменьшают precision; пропущенные и неуспешные ответы уменьшают recall. Подробные результаты и manifests сохраняются только в игнорируемые `var/` или `artifacts/`, в stdout выводятся статусы и коды блокировки. Кадры, описания клипов и разметка не публикуются.

В итоговом сравнении показывать также support каждого ракурса: число положительных и чистых уникальных записей, coverage, ошибки и неизвестность. Общий средний результат не заменяет таблицу по камерам; худший определённый результат показывается вместе с объёмом его данных. При нулевом знаменателе метрика остаётся `null`, а не становится 0 или 100%. Улучшение precision при потере прежних TP не принимается как улучшение модели по умолчанию; recall и F1 обязательны. Эти требования действуют и для будущего теста на видео судей.

## Что проверить на другом ракурсе

Аудит кода `ae9a95c` подтвердил: layout определяется для каждого видео, абсолютных зон одной камеры нет. Однако нормированные координаты не устраняют проекционные предположения:

- `ml/scene_items.py`: зона стола расширяется вверх на 35%, верхние 60% person box используются как область тела. Проверить, не отбрасываются ли предметы на столе и не принимаются ли предметы в руках за лежащие.
- `ml/scene_signals.py`: сигнал ключа использует область ниже/слева замка и фон справа; в коде отмечена настройка на одном ракурсе. Для двери и сейфа стартовый/медианный reference не устанавливает состояние «закрыто».
- `ml/scene_layout.py`: ограничения площади и вертикальности сейфа, запрос `a glass door` могут не подходить к новому виду сцены. `ml/events.py` использует горизонтальное смещение в одном из признаков ухода; движение в глубину кадра требует отдельной проверки.

Для каждого размеченного эпизода отделять ошибки layout, роли, видимости предмета, предложения VLM и финального отбора. Это задачи диагностики на новых данных, а не доказанные причины всех текущих ошибок и не основание заранее менять пороги. Одного успешного технического прогона без меток недостаточно для оценки полноты или precision.
