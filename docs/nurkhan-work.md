# Работа Нурхана: ML #2

Ветка: `feat/nurkhan-ml`. Область: оценка качества, baseline, VLM-проверка кандидатов. Основной `ml/pipeline.py`, фронтенд, бэкенд и нормативная база принадлежат другим участникам.

## Компоненты и интеграция

- `ml/eval.py`, `ml/evaluation_labels.py` — аудит разметки и независимое сравнение предсказаний с эталоном. Документация: `ml-evaluation.md`.
- `ml/baseline/` — локальные SigLIP-эмбеддинги и простой классификатор, запасной сигнал, а не юридическое заключение. Документация: `ml-baseline.md`.
- `ml/vlm/` — локальная проверка кандидатов, состояние `uncertain` сохраняет исходный кандидат вместо его удаления. Документация: `ml-vlm.md`.

Не менять контракты команды К1–К5 без согласования с Агыбаем. VLM не придумывает нормативные источники: используются только проверенные правила Олжаса.

Проверка после исправлений ревью PR #30: `origin/main` — `2f9dd5c`,
CV — `269f556`, pipeline — `215b51a` (PR #29/#31 ещё открыты).
В CV/pipeline/events-quality/scene-state `find_candidates()` по-прежнему напрямую
возвращает `[]`; у 42/42 строк annotations на этих refs и main нет `angle_id`.
Поэтому detector benchmark, обучение/holdout baseline и калибровка ещё не
разблокированы. Не выдавать пустой rules stage за настоящий отрицательный детектор.

`ml/vlm/pipeline_adapter.py` принимает оригинальные frozen Candidate команды.
Production `configure` прогревает модель один раз, `verify(..., budget_sec)` требует
явного остатка К2 и всегда сохраняет все исходные объекты/confidence даже при rejected.
`OwnerFrames` ограничивает отдельным процессом владельческий `ml.video.frame_at`
на CV index/FPS; legacy PTS-источник по-прежнему требует явной проверки таймлайна.
Свежий pipeline `215b51a` убрал `RuleText.basis`: адаптер поддерживает source-only
цитату из document/number_date/clause без изменения владельческого KB.
На его неизменённых Candidate/KB/assemble/video проверена синтетическая интеграция:

Только Box type alias заменён stub; детектор/качество не проверялись. Ранний snapshot

Ни pipeline, ни KB, ни сборщик не менялись; автоматического подключения VLM нет.
Детали — `ml-vlm.md`.

## Данные

Датасет находится вне репозитория. Пути передаются CLI-параметрами, не зашиваются в исходники. Видео, веса, кадры и реальные отчёты сохраняются в игнорируемых каталогах `data/`, `models/`, `artifacts/`.

Первичная проверка исходного `open_labels.xlsx`: 42 записи, 22 `нарушение`, 20 `без нарушения`. В командном PDF указано 23/19 — это расхождение необходимо сверить с Алпамысом. В именах смешаны латинская `X` и кириллическая `Х`. По решению Агыбая в ревью PR #30 для joins используется `ml.labels.normalize_video_name` (Х → X); буквальные исходные имена сохраняются для поиска физических файлов и provenance. Коллизии разных исходных имён внутри одного набора не должны молча объединяться.

Исходная бинарная разметка не содержит типов событий и ракурсов. Предоставленный позднее набор `analysis/` импортирован локально в `artifacts/provided-analysis/`: у всех 22 положительных записей есть первичный тип из каталога 17 типов, но `angle_id` отсутствует у всех 42. Качество на отложенном ракурсе нельзя заявлять до явной разметки ракурсов. Найдены две группы побайтовых дублей (40 уникальных содержимых); дубли должны целиком оставаться на одной стороне train/validation/test. Данные test нельзя использовать для обучения, подбора порога или выбора модели; для калибровки нужна отдельная validation-группа. Импорт не меняет командные `kb/` и не превращает нормативные утверждения в проверенные правила. Подробности — `analysis-import.md`.

## Среда и ограничения

На рабочей машине проверен Python 3.10 (`py -3.10`), CPU PyTorch, Transformers, NumPy и Pillow. CUDA недоступна. Системный `python` может указывать на другой интерпретатор без ML-зависимостей: команды в документации запускаются с явно выбранной средой.

**Решение команды: только собственные физические машины, без облачной аренды.** Vast.ai и другие облачные GPU/серверы для этой задачи не используются. Выполнена только проверка списка инстансов; аренды и переноса данных не было. Видео, кадры, эмбеддинги и inference остаются локально. Облачные AI-API также запрещены ТЗ §7 и FAQ 35. Подготовительное скачивание открытых весов допускается; после этого обработка работает без интернета. Публичный UI/API не отменяет локальности моделей: доступ к собственной машине организует Нариман. Локальный `.env.vast` исключён из Git и в разработке/запуске не используется; значение ключа не выводить, не коммитить и не переносить.

## Где запускать

Для текущего Windows-окружения evaluator/тесты запускаются через `.venv/Scripts/python.exe`; настоящий SigLIP smoke проверен через `py -3.10`. Отдельный CPU VLM runtime проверен через `artifacts/runtime-vlm/Scripts/python.exe` (Transformers 4.57.6, локальный SmolVLM-256M). Не смешивать глобальный `pip` с другим `python`. Все окружения, веса и реальные результаты игнорируются Git.

Пакетная label-free подготовка SigLIP завершена через `.venv/Scripts/python.exe`: `artifacts/baseline-full-cpu1/` содержит отдельные кэши всех 42 исходных ID, индекс и `validation.json`. Проверены 1464 конечных 768-мерных вектора, 40 уникальных содержимых, SHA256 и PTS всего набора. Это не обученная модель: `angle_id`, train/validation/test, обучение и пороги не подменялись. Успешный профиль — batch=1, CPU threads=2, локальный `models/siglip-base-patch16-224-vision-only` с точными исходными vision-тензорами; исходные веса сохранены. Предыдущий `artifacts/baseline-full/` содержит незавершённый прогон из-за commit limit Windows и не должен использоваться как полный набор.

## Проверка

```bash
python -m pytest -q
# Windows, интерпретатор с установленными ML-зависимостями:
.venv/Scripts/python.exe -m pytest -q
```

После финальных evaluator/VLM исправлений: 675 passed, 2 skipped (Windows sendmsg),
scoped Ruff/diff clean; actual audit и 42 cache-hash joins повторены offline.
Итоги исправлений ревью и проверок — `ml-verification.md`. Успешные unit-тесты
не означают проверку качества моделей. Для итоговых метрик нужны реальные
предсказания локального пайплайна; при их отсутствии отчёт показывает
необработанные видео, а не подменяет предсказания эталонными метками.
