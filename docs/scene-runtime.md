# Сцена в реальном пайплайне

`PIPELINE=real` выполняет детекцию и ролевые события, анализ сцены, правила и сборку ответа с настоящими JPEG-кадрами. `analyze(video_path, on_progress=None, time_budget_sec=None)` сохраняет контракт К2. VLM пока не подключена: её польза на процедурных нарушениях не подтверждена.

## Бюджет и запуск

На сцену резервируется 30 секунд, на завершение — 15 секунд. Сцена получает общий абсолютный deadline; ожидание модели учитывается в том же бюджете. Когда времени мало или сцена завершилась с ошибкой, правила используют события и COCO-предметы. `export ML_SCENE=0` отключает сцену для сравнения; переменная читается из окружения процесса.

Проверки deadline кооперативные: уже начавшиеся native decode, загрузка весов и forward нельзя прервать. Это не гарантия жёсткого SLA. Бэкенд отдельно помечает просроченное задание как `failed` и удерживает вычислительный слот до окончания его потока.

Установить ML-зависимости из `ml/requirements.txt`. Веса RT-DETRv2 и OWLv2 должны быть заранее доступны локально; версии и лицензии указаны в [licenses.md](licenses.md). Видео и кадры обрабатываются локально. OWLv2 загружает только локальные safetensors закреплённой ревизии.

## Воспроизводимая оценка

Из корня репозитория, в активированном окружении:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 python -m ml.tools.run_dataset \
  --out var/runs/full.json --capture var/cache/full
```

После прерывания добавить `--resume` к той же команде. Успешные результаты сохраняются, ошибки пересчитываются. Для новой версии кода, настроек или весов использовать новые пути: продолжение чужого прогона смешивает эксперименты. Checkpoint записывается после каждого видео атомарно.

```bash
python -m ml.tools.run_dataset --score var/runs/full.json
python -m ml.tools.run_dataset --rules-only var/cache/full
```

`--rules-only` пересчитывает правила на сохранённых входах с тем же отбором кандидатов, что у API: каталог, confidence, объединение эпизодов и максимум пять нарушений. Извлечение доказательств не выполняется: кандидат, для которого API не смог бы получить кадр, здесь может остаться. Время детекции, сцены и доказательств при этом не измеряется. Pickle-файлы предназначены только для доверенных локальных артефактов этого инструмента; не загружать сторонние файлы.

В 42 исходных файлах 40 уникальных видео: X-4/X-47 и X-5/X-48 — дубликаты. Отчёт считает группу один раз и допускает любой из размеченных таймкодов пары. Ошибки обработки остаются в знаменателях accuracy и recall. Это оценка на открытом наборе, по которому разрабатывались правила; она не заменяет проверку на отложенном ракурсе.

Recall, precision и accuracy относятся к бинарному вердикту на уровне видео. Совпадение типа и попадание таймкода ±2 секунды считаются отдельно по любому выданному кандидату: это не совместная метрика «правильный тип в правильный момент».

## Известные ограничения

- `safe_open` и `door_open` измеряют изменение относительно опоры. Открытое на старте состояние может инвертировать сигнал при закрытии; низкое значение не доказывает физическое «закрыто». Проверка истории в правилах ограничивает артефакты, но не устраняет эту неоднозначность.
- Сигнал ключа экспериментальный: недостоверные, закрытые человеком, изменившиеся при движении дверцы или освещении измерения исключаются. Без надёжно замеченного отсутствия и появления ключа возвращается неизвестное состояние. Confidence этого типа остаётся ниже порога ответа.
- Смена посетителей через стеклянную дверь и короткие визиты могут давать лишние общие события входа/выхода.
- Возврат денег, порядок пересчёта и другие процедурные действия текущие правила надёжно не распознают. Их качество нужно проверять отдельным экспериментом VLM.
