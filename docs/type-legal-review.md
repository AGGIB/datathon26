# Предварительная правовая оценка общих типов

**Правовая оценка и принятая индикаторная политика от 17.10.2026.** Сохранены общие ID 17 основных типов Т01–Т17 и 15 дополнительных проверок Д01–Д15. По решению тимлида создан [каталог индикаторов](../kb/violations.yaml): 27 активных, 5 исключённых. Это не ground truth и не результат анализа конкретных видео. Визуальная проверка нами не выполнялась.

[Машиночитаемое сопоставление](../kb/legal/type-mapping.json) содержит 32 записи, 82 точные цитаты в `types[].refs` и 6 цитат переходных положений в `metadata.temporal_refs`. В каждой записи есть стабильный ID / нейтральный заголовок, группа, оценка, источник / пункт / URL / цитата, необходимый контекст, общие наблюдаемые проверки, ограничения и отдельное поле `teamlead_policy`. Примеров видео, частных наблюдений, ID клипов, таймкодов и оценок датасета в этом файле нет. Проверка работает без игнорируемого каталога `data/`.

Аналитические оценки сохранены: **19 условно применимых оснований, 7 типов без прямого основания в заявленном названии, 6 типов, требующих невизуальных данных**. Они описывают прямоту правового основания исходной формулировки, а не состав активного каталога; редакционное смягчение названий само по себе эти оценки не меняет. Политика принята как набор индикаторов возможного нарушения; `supported_detectors=0`, у всех аналитических записей `pipeline_status=not_integrated`, у записей каталога `implementation_status=not_implemented`. Локальная валидация ещё необходима. Backend, frontend и ML в этой работе не изменялись.

Активны все Т01–Т17 и Д01–Д04, Д06, Д08–Д11, Д13. Исключены Д05, Д07, Д12, Д14, Д15; причины — в [ограничениях](limitations.md). Т04 оставлен активным по решению тимлида с `normative_basis: pending` и пометкой «нормативное основание уточняется»; ключа `rule` у него нет. У остальных 26 индикаторов есть основная ссылка, у части — дополнительные: всего в каталоге 46 цитат. Наличие ссылки не подтверждает применимость к конкретному событию.

## Как читать статусы

- `conditional` — правовое основание возможно лишь после установления перечисленного контекста и исключений. Наблюдаемый признак не равен доказанному нарушению.
- `no_direct_basis_as_named` — приведённая норма не устанавливает прямой запрет, сформулированный в названии черновика. Ссылка автора не делает этот вывод юридически подтверждённым.
- `requires_nonvisual_evidence` — нужны документы, полномочия, суммы, системные настройки или иные сведения, не устанавливаемые обычным видеопризнаком. Запись оставлена в review с причиной, а не объявлена поддержанным детектором.

## Границы источников и трактовки

Источников 8, перечень и реквизиты — в [реестре](../kb/sources.md). Все снимки сообщают состояние документов на **14.10.2026**, обновление базы 16.10.2026; загрузка / проверка 17.10.2026 не гарантирует полноту законодательства на 17-е. Применимость к дате конкретного события проверяется отдельно.

До 01.01.2027 применяется временный п.16 №14. Открытая дверь не тождественна нарушению требований к её устройству. По №231 различаются приём банком от инкассации (п.24–25) и приём инкассатором от клиента (п.107); рабочий сейф не подменяет кладовую / сейфовую комнату. Для Т01 основной п.61 о банкнотах с признаками подделки отделён от сомнительных банкнот; дополнительные п.59 / 63 сохраняют условия допустимого возврата после экспертизы. В п.59 сохранены все четыре абзаца, включая условия возврата после экспертизы и невозврата неплатёжных денег. По п.75 ответственное за сохранность лицо допускается непосредственно, другое лицо — по распорядительному документу с сопровождением ответственного; эти категории не объединяются в одно обязательное сочетание условий.

Т13 в аналитическом JSON и активном каталоге ограничен обычной банковской кассой и №14 п.8. `ordinary_bank_cashdesk` — решение тимлида, не результат нашего просмотра видео. №49 п.41 об обменных пунктах и №231 п.75 о кладовой / сейфовой комнате не используются для Т13. Пересечение установленной границы кассовой стороны не доказывает отсутствие полномочий.

№53 п.71 подп.9 относится к системной неактивности более 30 минут, предусматривает завершение сеанса либо блокировку с повторной аутентификацией и применяется с исключениями п.72. Отсутствие человека не равно системной неактивности. Для немедленной блокировки при уходе нужно конкретное внутреннее правило; краткий фрагмент не подтверждает нарушение системного таймаута. Эти ссылки сохранены в аналитическом review Т04, но не перенесены в его активный `rule`. Общая дата введения №53 18.04.2026 рассчитана по десятидневному правилу после публикации 07.04.2026; это не поле инфокарточки.

Банковская тайна рассматривается по действующим частям ст.69 нового закона, с составом сведений и допустимым раскрытием по п.1–4. Ст.69 п.19 вводится только с 01.01.2027. П.7-2 ст.50 прежнего закона сохраняется до 01.01.2027; полная отмена старой ст.50 не утверждается. Общая дата введения нового закона 19.03.2026 — расчёт по ст.135 после публикации 17.01.2026, с исключениями. Будущее дополнение ст.9 закона о персональных данных с 01.01.2027 не применяется. Эти переходные положения подкреплены цитатами `metadata.temporal_refs`.

Конфиденциальность персональных данных ограниченного доступа требует учитывать согласие или иное законное основание. Не все сведения принципиально невидимы, но наличие бумаги, экрана или второго посетителя не доказывает разглашения. Доступ, режим данных и полномочия получателя требуют подтверждения. По ТЗ распознавание / идентификация лиц запрещены.

AML допускает иные источники информации и предусмотренные законом способы / исключения надлежащей проверки. Это не отменяет самостоятельную визуальную идентификацию по №231 п.19 подп.1. Архивные требования №49 относятся к обменному пункту; срок хранения 90 дней, резервирование и защита записей не выводятся из длительности клипа.

## Проверка и дальнейшее использование

`python3 -B tools/validate_legal_kb.py` проверяет JSON и YAML, 32 аналитических ID и состав каталога 27/5, группы / enum / статусы, ссылки и якоря, SHA256, наличие полных локальных текстов и точное вхождение цитат с нормализацией только whitespace / NBSP. Проверяется `text_sha256`, точное вхождение цитат в текст и наличие ссылочных якорей в историческом `snapshot_anchor_ids`, сведения сохранённого среза, условия Т04 / Т13, исключения, командные эвристики и контракт шаблонов. HTML для запуска не требуется; DOM-якоря и живые страницы офлайн не перепроверяются. Нужен PyYAML из [requirements](../tools/requirements-legal.txt); команды установки и изолированной проверки — в [README](../kb/legal/README.md). Валидатор не оценивает юридическую истинность и не обращается к датасету.

Цитаты извлечены из официальных HTML без добавления отсутствующих вводных фраз или склейки пропущенных подпунктов. Для непрерывных выдержек подп.19(2) / 31(4) сохранены промежуточные подпункты. Исходные HTML и инфокарточки сохранены побайтно в игнорируемом `data/legal-source-backup/`; их исторические хеши отделены от хешей текстовых снимков. Индекс якорей фиксирует первоначальное извлечение, а не новую DOM-проверку.

Следующие шаги: проверить контекст и наблюдаемость принятых индикаторов локально, затем отдельно решать интеграцию. При обработке нельзя передавать облачным AI видео, кадры или их описания. Сервис, UI / API и качество ML пока не проверялись.
