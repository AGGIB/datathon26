# Импорт предоставленных типов и анализа

Предоставленные `Типы нарушений.docx` и каталог `analysis/` — входные материалы команды, не готовая модель. Исходные файлы не изменяются. Закрытые описания сцен и evidence не выводятся в чат, stdout или облачные AI-сервисы.

## Что делает адаптер

```bash
python -m ml.import_analysis \
  --analysis-dir 'C:/local/analysis/analysis' \
  --labels 'C:/local/open/open_labels.xlsx' \
  --videos-dir 'C:/local/open/videos' \
  --output artifacts/provided-analysis
```

Адаптер читает структурированные `report_data.json` и `manifest.json` из набора, не исполняет чужие скрипты. Сопоставление подтверждается SHA256 настоящих локальных файлов. Если одинаковое содержимое есть в нескольких именах, дополнительно требуется точное имя из manifest. Кириллица/латиница, регистр и идентификаторы типов не исправляются автоматически.

Экспортирует только в игнорируемый `artifacts/`:

- `annotations.csv` — первичный тип и исходный пиковый таймкод для каждого видео; наблюдения копируются локально как предоставлены, без новых выводов модели;
- `catalog.draft.json` — каталог типов с исходными кодами, признаками и **непроверенными** нормативными утверждениями;
- `baseline-manifest.draft.json` — имена файлов, бинарные метки, временные якоря, content SHA256 и явно предоставленные ракурсы;
- `additional-checks.unverified.json` — дополнительные гипотезы отдельно от подтверждённого каталога;
- `provenance.json` — связь с исходными записями, исходные названия и интервалы без переинтерпретации;
- `summary.json` — только числовая сводка и ограничения.

## Что не считается готовым

1. Наличие правовой ссылки в отчёте не является проверкой нормы. Все импортированные типы имеют `verified=false`, `rule=null`. Олжас должен проверить применимость, точную цитату и актуальность источника; код не превращает утверждения из документа в закон автоматически.
2. Импорт сохраняет один **предоставленный первичный тип** на положительную запись. Это не подтверждение полноты списка событий, особенно если в одном видео их несколько.
3. Из текстового интервала не выдумываются `t_start`/`t_end`; эти поля остаются пустыми до структурированной разметки. Пиковый таймкод сверяется с XLSX.
4. Если `angle_id` отсутствует, записывается `unknown`, обучение/проверка отложенного ракурса не заявляются. Не заменять неизвестные ракурсы случайными буквами.
5. Совпадающий content SHA256 должен оставаться на одной стороне train/validation/test, даже если имена разные. Поля SHA256 в draft manifest позволяют это проверить до обучения.
6. Кадры, исходные наблюдения, импортированные файлы и model weights в Git не добавляются. Командные `kb/annotations.csv` и `kb/violations.yaml` автоматически не перезаписываются: их владельцы — Алпамыс и Олжас.

## Согласование с командным каталогом

В актуальном `main` исходные коды связаны со стабильными `id` полем `codex_code`. Локально подготовлен отдельный `annotations.team.csv`: `type_id` согласован с этим явным отображением, `source_type_code` сохраняет исходный код, а имена видео остаются буквальными. `type-id-map.json` и `video-id-map.json` фиксируют преобразование для аудита; это не молчаливое исправление идентификаторов.

`vlm-rules.from-team.json` включает только записи, которые в командном каталоге имеют `status=verified`, непустой `rule.verified_by` и документ/цитату/URL. Экспортировано 16 таких записей; одна draft-запись не повышалась до verified. Это доверие явно помеченному каталогу команды, не независимая правовая проверка данного адаптера. Все эти файлы остаются в локальном `artifacts/`.

## Что установлено на предоставленном наборе

Локальный импорт сопоставил все 42 файла: 22 положительных записи получили предоставленный тип, 20 отрицательных — `none`. В каталоге 17 типов, 15 дополнительных проверок и 7 источников. Ракурсов нет ни у одной записи.

Найдены две группы побайтовых дублей: `Х-4.mov` / `Х-47.mov` и `Х-5.mov` / `Х-48.mov`. У каждой пары бинарные метки согласованы; это 40 уникальных содержимых, а не 42 независимых видеозаписи. Группы нельзя разносить по обучению и оценке.

В переданных Python-скриптах статически обнаружены ffmpeg, Pillow и генерация Word/JSON. Облачных SDK в их импортах не обнаружено. Это не доказывает происхождение всех готовых текстовых наблюдений и не является сертификацией полного процесса их подготовки.
