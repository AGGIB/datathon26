Визуальные наблюдения нами не подтверждены; реализованных детекторов 0, реальных проверок сервиса и итоговых результатов QA / ML нет. Выполнение пунктов ниже не подтверждено. Основание: локальный оригинал «Кейс_ForteBank.docx», разделы 4–10 и FAQ. Backend, frontend, ML и таксономия остаются в зоне владельцев; ниже предусмотрена совместная сверка.

## Источники и объяснения

- [ ] Проследить цепочку **источник → точная цитата → редакция → условия → согласованный тип → видимое событие → кадр → таймкод** (разделы 6, 8; критерий 4 раздела 9).
- [ ] Проверить субъект, дату действия нормы, исключения, область помещения и операции. Для п.16 №14 использовать временную редакцию до 01.01.2027; не приравнивать открытую дверь к нарушению требований к её устройству.
- [ ] Совместно с Алпамысом локально проверить применимость каждой связи принятого каталога с наблюдаемым событием. Принятие индикаторной политики не считать подтверждением юридического факта; отдельный пул кандидатов не является перечнем детекторов.
- [ ] Проверить условия Т04 без `rule`, Т13 только с №14 п.8 для обычной банковской кассы, пороги Т06 / Т09 только на ветвях работы на месте и выбор одной ветви описания Т06. Качественные confidence не представлять как измеренную вероятность. Полные условия — в [ограничениях](limitations.md).
- [ ] Совместно с ML проверить, что все 27 шаблонов используют `{t}` / `{observation}` и загружаются без fallback; у 26 правил окончание `Основание: {rule_document}, {rule_clause}.`, у Т04 — `Нормативное основание уточняется.`. Для Т06 заполнять `observation` только одной выбранной ветви.
- [ ] Совместно с ML проверить, что кадр и таймкод относятся к описанному событию, а описание не содержит догадок о проводках, сверке, полномочиях или действии вне обзора (разделы 5–7).
- [ ] Проверить случаи окклюзии, неполного ракурса, короткого / обрезанного видео: не делать вывод об отсутствии действия или предмета лишь потому, что они не видны.

## Совместная сверка UI и API

- [ ] С владельцами frontend / backend пройти сценарий загрузки, статуса и получения результата; сверить типы, таймкоды, описания и кадры между UI и API (разделы 4–5, 10).
- [ ] Проверить два результата UI: «Нарушение не обнаружено» и «Обнаружены признаки возможных нарушений»; API: `no_violation` / `violation`, список `violations` пуст при отсутствии событий. Не добавлять третий вердикт в контракт (разделы 4, 10).
- [ ] Проверить, что отсутствие `rule` само по себе не меняет вердикт; у Т04 отображается «нормативное основание уточняется». Описания должны сохранять наблюдаемый факт и условную формулировку без категорических обвинений.
- [ ] С владельцем backend проверить `X-API-Key`, отклонение запросов без верного ключа, `POST /api/v1/analyze` с полем `file` и `.mov`, возврат `job_id`, затем `GET /api/v1/jobs/{job_id}` со статусами `processing`, `done`, `failed` (раздел 10; FAQ25).
- [ ] Проверить результат: `type`, `timecode_sec`, `description`, от 1 до 3 кадров в `evidence_frames` с `timestamp_sec` и `image_base64`; декодированный формат JPEG. Источник и правило проверить в UI / документации; не добавлять обязательные поля в API-схему от себя (разделы 4, 8, 10).
- [ ] С владельцами backend / ML измерить завершение обработки до 5 минут, доступность адресов UI / API и обработку нового видео без ручного запуска (разделы 5, 10; FAQ14, 23).
- [ ] С владельцами backend / ML проверить битый файл и неполное видео: понятная ошибка / согласованный статус, отсутствие зависания и выдуманного доказательства. Это проверки устойчивости команды; ТЗ не задаёт точный текст ошибки или отдельный HTTP-код для этих случаев.

## Ограничения данных и воспроизводимость

- [ ] Совместно с владельцами подтвердить локальность моделей и отсутствие передачи облачным AI видео, кадров **или их описаний**. Проверить обработку без интернета после загрузки весов (раздел 7; FAQ21, 35).
- [ ] Все операции с видео выполнять локальным кодом; не открывать и не анализировать видео или кадры инструментами облачного чата.
- [ ] Не публиковать и не передавать третьим лицам тестовые данные, не использовать тестовые видео для обучения; соблюдать использование данных только в рамках хакатона (раздел 10; FAQ6).
- [ ] Проверить отсутствие анализа звука и распознавания / идентификации лиц (FAQ28–29).
- [ ] После появления сервиса и разрешённых материалов записывать дату, версию, ожидаемый и фактический результат, владельца исправления. До этого не отмечать проверки пройденными и не заявлять метрики.

200 МБ, цель 60 секунд, 2 воркера, ±2 секунды и 0.95 — внутренние цели из командного PDF, не критерии ТЗ. В ТЗ / FAQ14 указан лимит 5 минут, FAQ17 требует конкретный кадр и таймкод без допуска ±2 секунды. HTTP-скрипты без работающего сервиса не добавлялись.
