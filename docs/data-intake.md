# Приём и технический аудит данных

Материалы переданы пользователем 17.10.2026. Аудит выполнен локально: чтение XLSX / DOCX / JSON, SHA256 файлов и статический AST-разбор скриптов. Видео, звук и изображения не декодировались; визуальные наблюдения и приблизительные таймкоды нами не проверялись и не уточнялись.

После NFC-нормализации и явного сравнения Latin `X` / Cyrillic `Х` коллизий имён, повторных ID, отсутствующих видео или лишних видео относительно меток и manifest не найдено. Реестры DOCX / JSON совпадают по ID. Ключ сравнения используется только для сопоставления; исходники не переименовываются. При двух именах с одним ключом валидатор сообщает неоднозначность и исключает всю группу из автоматического сопоставления.

Все 22 заданных таймкода разобраны как секунды, включая запись минут и секунд, и находятся в пределах длительностей из manifest. Эти длительности **записаны автором пакета, а не измерены аудитом**; применены только после совпадения SHA256 соответствующего MOV. При несовпавшем / отсутствующем хэше длительность получает `unverified`, проверка границ по ней не выполняется. Приблизительные таймкоды не превращены в точную покадровую разметку.

## Дубли содержимого и неоднозначная разметка

Есть две пары побайтно одинаковых видео; внутри каждой пары бинарные метки совпадают. В одной группе исходные таймкоды различаются. Аудит сохраняет значения локально и выдаёт `duplicate_content_multiple_timestamps`; частные ID и таймкоды здесь не публикуются. Это не доказывает ошибку разметки: наличие и количество событий нами не проверялись. Единственный правильный таймкод не выбирался; нужна согласованная схема оценки. Для будущих данных предусмотрен `duplicate_content_label_conflict`.

Рекомендация Нурхану: группировать train / validation split по SHA256, чтобы одинаковое видео не попало в обе выборки. Аудит не исключает, не переименовывает и не перемечает файлы автоматически. Локальный отчёт содержит исходные значения и технические ключи без описаний клипов.

## Происхождение авторского анализа

Готовый анализ — **черновик команды, не эталон организаторов**. Названия типов являются гипотезами, не подтверждёнными нарушениями и не ground truth для классификации. Совпадение DOCX с JSON подтверждает согласованность двух представлений черновика, но не правильность юридической трактовки или наблюдений. [Правовое сопоставление общих типов](type-legal-review.md) выполнено отдельно в зоне Олжаса. По решению тимлида на его основе создан [каталог](../kb/violations.yaml) из 27 активных индикаторов и 5 исключённых типов; принятие политики не подтверждает частные наблюдения или качество ML.

В пакете 7 Python-скриптов; статический разбор обнаруживает устаревшие личные абсолютные пути во всех семи. По проверке структуры кода пакет содержит извлечение кадров / контактные листы, сборку DOCX и сохранение заранее заданных записей в `write_visual_second.py`. Скрипты не запускались и не импортировались. Наличие этих инструментов и готовых записей не доказывает существование воспроизводимого классификатора / ML. Методологию и происхождение оценок нужно уточнить у автора; вывод о том, кто делал анализ — человек или AI, не устанавливался.

В обработке соблюдается раздел 7 ТЗ: облачным AI нельзя передавать видео, кадры или их описания. Исходники и отчёт находятся в игнорируемом `data/`; описания клипов, изображения, PDF с кадрами и видео в Git не копируются. `.DS_Store` игнорируется, существующие файлы не удаляются.

## Повторный запуск

Из корня репозитория с Python, содержащим `openpyxl` и `python-docx`:

```sh
python3 -B tools/audit_dataset.py
python3 -B tools/check_audit_dataset.py
```

Все входные пути настраиваются через CLI (`--labels`, `--videos`, `--manifest`, `--taxonomy`, `--report-data`, `--visual-first`, `--visual-second`, `--sheet`, `--expected-count`). В коде нет личных абсолютных путей. `manifest.file` используется только как техническое имя файла, исходный абсолютный путь не исполняется и не открывается.

JSON пишется только в `data/audit/`, по умолчанию `data/audit/intake.json`; иной файл в этом каталоге можно задать через `--output`. В stdout идут только агрегаты и коды технических проблем. Код завершения 0 допускает явно перечисленные предупреждения, 1 означает ошибки сверки, 2 — невозможность аудита / неверный вход. Синтетические проверки покрывают русские минуты / секунды, коллизии X / Х, дубли содержимого с несколькими таймкодами и конфликтом метки, SHA256 перед проверкой границ, размеры и отказ от исполнения сторонних скриптов.
