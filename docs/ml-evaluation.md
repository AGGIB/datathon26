# Локальная оценка ML: Нурхан

`ml.evaluation_labels` и `ml.eval` работают на стандартной библиотеке Python 3.10+.
Существующий командный `ml.labels` сохранён без изменения публичного API.
Установка библиотек, скачивание моделей и сетевые сервисы не нужны.
Здесь нет классификатора: `score` сравнивает **готовые** ответы локального пайплайна с эталоном,
а `run` запускает настоящий `analyze()` в ограниченных локальных subprocess и затем считает тот же отчёт.
Все примеры ниже синтетические, не являются предсказаниями на конкурсных видео.

## Конфиденциальность

Видео, кадры, описания сцен и содержимое настоящих отчётов нельзя отправлять внешним AI/API.
Аудит запускает только локальный `ffprobe`, если он найден в `PATH`: длительность,
разрешение, FPS, time base, число кадров и размер. Кадры не извлекаются и не анализируются.
Поля тегов и текст stderr `ffprobe` в отчёт не попадают. Таймаут одного вызова — 20 секунд.
Отсутствие `ffprobe` не мешает аудиту; отключение: `--no-ffprobe`.

Настоящие отчёты сохранять **только в игнорируемом `artifacts/`**. Не добавлять их в Git.
CLI печатает агрегированную числовую таблицу и режим/число записей, без построчной разметки и описаний.
Не подменять отсутствующие ответы эталонными метками или синтетическими результатами.

## Команды

Из корня репозитория:

```bash
python -m ml.eval audit --labels "C:/path/open_labels.xlsx" --videos-dir "C:/path/videos" --output artifacts/ml-evaluation/audit
python -m ml.eval score --labels "C:/path/open_labels.xlsx" --predictions artifacts/predictions.json --output artifacts/ml-evaluation/score
python -m ml.eval score --labels "C:/path/open_labels.xlsx" --predictions artifacts/predictions.json --annotations "C:/path/annotations.csv" --split "C:/path/split.json" --subset test --output artifacts/ml-evaluation/holdout
python -m ml.eval run --labels "C:/path/open_labels.xlsx" --videos-dir "C:/path/videos" --annotations "C:/path/annotations.csv" --output artifacts/ml-evaluation/current
python -m unittest discover -s tests -v
```

`audit`: рекурсивное сопоставление файлов, пропуски, неоднозначные дубликаты,
число файлов без меток, исходное распределение классов, необязательные числовые метаданные,
проверка, не выходит ли временной якорь за длительность видео.
`.mov`, `.MOV` и файлы без расширения перечисляются, но расширения не исправляются автоматически.

`score`: `--annotations` и `--split` необязательны.
Те же поля доступны у `run`. По умолчанию вызывается `ml.pipeline:analyze`; другой локальный target
передаётся `--pipeline module:function`. Мягкий бюджет `--time-budget-sec 240`, жёсткий `--timeout-sec 300`.
Подробности изоляции и cold-start измерений — в `ml-runner.md`.
Нереализованный pipeline возвращает ошибки, а не фиктивные чистые результаты.
Без split выбирается `all`; со split по умолчанию `test`.
`--subset train|test` без split — ошибка. `--subset all` со split всё равно проверяет изоляцию ракурсов.
Ошибки входного формата дают код возврата 2; перед валидацией входов отчёт не создаётся.

## Исходные метки

XLSX читается через `zipfile` + `xml.etree.ElementTree`: первый лист по relationship,
inline/shared strings, разреженные ячейки, числовые секунды. Формулы, булевы значения
и error cells не принимаются; форматирование Excel не интерпретируется как время суток.
Числовые Excel-идентификаторы запрещены, чтобы не менять их текстовую запись.
CSV: UTF-8 / UTF-8 BOM, запятая, точка с запятой или табуляция.

Колонки, в произвольном порядке:

| Смысл | Исходный заголовок | Алиас CSV |
|---|---|---|
| Идентификатор видео | `наименование файла` | `video` |
| Секунды / временной якорь | `таймстемп` | `timestamp` |
| Бинарная метка | `нарушение / без нарушения` | `label` |

Значения метки: `нарушение`, `без нарушения` (регистр и краевые пробелы метки несущественны).
Пустой timestamp — неизвестный якорь, не нулевая секунда. Неизвестные метки и дубликаты — ошибка.

Идентификаторы сохраняются буквально: Latin `X` и Cyrillic `Х` различны.
Только **точное необязательное конечное `.mov`** снимается при сопоставлении:
`X_synthetic` соответствует `X_synthetic.mov`, но не `Х_synthetic.mov`,
`X_synthetic.MOV` или `X_synthetic.mp4`. Регистр, Unicode, пробелы не нормализуются.
Пути вместо идентификаторов и краевые пробелы запрещены. Два предсказания на один
идентификатор, в том числе с/без `.mov`, запрещены.

Поддерживаемое время: число секунд; `22`; `1.5`; `22 секунда`;
`1минута 8 секунда`; `01:08`; `01:02:03`; дробные секунды в последней компоненте.
Русские формы `минута/минуты/минут/мин/м`, `секунда/секунды/секунд/сек/с` поддерживаются.
Компоненты секунд/минут после двоеточия < 60.
Отрицательные значения, NaN, infinity, bool, мусор и неверные компоненты не исправляются, а отклоняются.
Числовая ячейка Excel трактуется как секунды, **не** как доля суток.

## JSON предсказаний и API-конверт

Файл — список записей либо ровно одна обёртка `{"predictions": [...]}` или `{"results": [...]}`.
Поля записи:

- `video` (или `video_id`): буквальный идентификатор; при наличии обоих они должны соответствовать одному видео.
- `status`: `done` (К1), `ok`, `success`, `completed` — завершённый ответ; `failed`/`error` — ошибка;
  `timed_out`/`timeout`/`timedout` — таймаут. Другие/отсутствующие статусы невалидны.
- `verdict`: `нарушение`/`violation` либо `без нарушения`/`нарушений нет`/`no_violation`;
  сравнение без учёта регистра. Это бинарный вердикт, не юридическая квалификация.
- `violations`: список объектов. Чистый вердикт с непустым списком — противоречие и invalid.
  Положительный бинарный вердикт с пустым списком допустим только для legacy-статусов `ok/success/completed` (без подтверждения локализации). Для канонического `done` из К1 это invalid.
- `elapsed_sec`: необязательное конечное неотрицательное время обработки. Отсутствующее время — unknown,
  а не нулевая длительность и не успешный SLA.
- Событие: стабильный `type_id` предпочтительнее отображаемого `type` (иначе `unknown`), `t_start`, `t_peak`, `t_end`.
  Каноническое поле К1 `timecode_sec` используется как пик; конфликт с `t_peak` даёт invalid.
  Присутствующие времена парсятся строго; порядок `t_start <= t_peak <= t_end` обязателен.
  Без `t_peak` событие не участвует во временном сопоставлении; середина интервала не выдумывается.
- Поддерживается конверт: `video`, `status`, `elapsed_sec` снаружи, `verdict`, `violations` внутри `result`.
  Противоречащие друг другу внешние/вложенные `verdict` или `violations` дают invalid.
  Дополнительные поля API не используются; описания сцен не копируются в отчёт.

Синтетический пример:

```json
{
  "predictions": [
    {
      "video": "X_synthetic.mov",
      "status": "ok",
      "elapsed_sec": 12.5,
      "result": {
        "verdict": "violation",
        "violations": [
          {"type": "synthetic_type", "t_start": 20, "t_peak": 22, "t_end": 25}
        ]
      }
    }
  ]
}
```

Отсутствующее видео получает `missing`. Невалидный ответ, который можно связать с видео,
получает `invalid`, а не отрицательный вердикт. Неидентифицируемая запись,
неизвестный ID или дублирующиеся ID останавливают запуск: безопасно угадать адресата нельзя.
Для `failed`/`timed_out` вердикт не используется независимо от его содержания.

## Ручная `annotations.csv`

Синтетический пример:

```csv
video,type_id,t_peak,angle_id
X_synthetic,synthetic_type,22,synthetic_camera_a
X_synthetic,synthetic_type,45,synthetic_camera_a
Х_synthetic,,,synthetic_camera_b
```

Одна строка — одно известное событие; строка без type/time задаёт только ракурс.
Поддерживается командная колонка `type_id`; старый алиас `type` также принимается.
Строка отрицательного видео с `type_id=none` и пустым временем не создаёт событие.
Для видео с событиями этот список заменяет одиночный якорь XLSX и считается предоставленным
эталонным списком; его полноту необходимо проверить вручную.
Неизвестные ракурсы/типы не определяются по имени или изображению.
Разные ракурсы для одного видео, дубли событий, события на отрицательном видео,
тип без `t_peak`, некорректное время — ошибки.
Пустые тип/ракурс становятся `unknown`; для holdout unknown недопустим.

## Изолированный angle holdout

Split CSV содержит `video,subset,angle_id`, по одной строке на **каждое** размеченное видео.
`subset`: только `train` или `test`. Альтернатива — JSON:

```json
{
  "train": [{"video_id": "X_synthetic", "angle_id": "synthetic_camera_a"}],
  "test": [{"video_id": "Х_synthetic", "angle_id": "synthetic_camera_b"}]
}
```

Для совместимости с baseline ключ `holdout` вместо `test` поддерживается в JSON.
Обе стороны обязательны и непусты. Все ID должны быть известны и уникальны;
ракурсы train/test не пересекаются, unknown запрещён, split и annotations согласованы.
Валидация проверяется на **полном** наборе, до выбора подмножества.
Ответы на известные видео вне выбранного подмножества не оцениваются;
их количество видно в `split.excluded_predictions`.

Проверка split предотвращает структурную утечку одинаковых ракурсов.
Она не доказывает, на каких видео действительно обучалась модель: не использовать test
для обучения, подбора порога, отбора кадров или выбора модели; нужна отдельная validation-группа.
При отсутствии split отчёт **не** заявляет проверенный angle holdout.

## Метрики и знаменатели

- `confusion`: TP/TN/FP/FN **только валидных** ответов + `abstain_positive`, `abstain_negative`.
  Ошибка/таймаут/invalid/missing никогда не становятся TN.
- `coverage = scored / total`. `status_counts`, `label_counts` показывают состав знаменателя.
- `scored_only`: accuracy/precision/recall/F1 условны по валидным ответам.
- `end_to_end`: accuracy = (TP+TN)/все видео; precision = TP/(TP+FP);
  recall = TP/все положительные; F1 = 2TP/(2TP+FP+FN+abstain_positive).
  Необработанные отрицательные также уменьшают accuracy, но не превращаются в FP/TN.
  Нулевой знаменатель даёт JSON `null`, а не придуманную единицу.
- `misses`: все положительные, которые не дали TP, включая пропуски/ошибки;
  `false_positives`: только фактические FP.
- `processing_time`: число известных длительностей, сумма, среднее, максимум.
  Это заявленное исполнителем elapsed, а не время чтения отчёта оценщиком.
- `sla`: валидный завершённый ответ и известное elapsed <= **300 секунд**.
  Доли `rate_total` и `timely_correct_rate_total` имеют знаменатель все выбранные видео.
  `unknown_elapsed` не считается успехом; `completed_late` показывает поздние ответы.
  Качество `end_to_end` отдельно от SLA: поздний завершённый ответ может быть правильным,
  но не увеличивает timely-correct. Явный timed_out не оценивается как завершённый ответ.
- `localization`: минимальная суммарная абсолютная ошибка при максимальном числе
  **взаимно-однозначных** пар событий одного видео. Динамическое программирование по
  отсортированным временам, а не жадный nearest neighbour. Один predicted peak нельзя
  засчитать дважды. Есть число эталонных, предсказанных, сопоставленных и несопоставленных
  событий, MAE в секундах. События без peak — несопоставленные predicted events.
- По умолчанию допуск равен 2 секундам: `within_tolerance` и `within_tolerance_rate_truth`
  считают корректно локализованные события относительно всех эталонных событий, включая пропуски.
  Даже далёкая пара входит в MAE, поэтому `matched_events`
  **не является** числом корректных детекций. Пропуски не входят в MAE и видны в отдельном
  счётчике; хороший MAE без покрытия недостаточен.
- Только XLSX-метка даёт максимум один якорь и не доказывает полный список событий:
  `label_only_limited=true`. Несопоставленные predicted events здесь нельзя трактовать
  как доказанные ложные события. Неизвестный peak не заменяется нулём.
- `types`: исходные счётчики событий плюс условная точность типа на временно сопоставленных
  парах в пределах допуска **только видео с полностью известными эталонными типами** (и отрицательных видео).
  `type_confusion` показывает матрицу типов; `<missed>`/`<spurious>` отмечают пропущенные/лишние события.
  Неизвестная/частичная разметка исключается из знаменателей type precision/recall;
  знаменатели показаны явно. Это не юридическая проверка и не AP/mAP детектора.
  Метрики `unknown` — null. Флаг `type_metrics_limited` предупреждает об ограничениях.
- `angles`: численность, число обработанных и правильных ответов по явно заданному ракурсу,
  либо группа `unknown`. Ракурс не выводится из видео.

## Выходные файлы

В обоих режимах: `overall.json` (агрегаты, режим, параметры split),
`per_video.json`, `per_video.csv` (UTF-8 BOM для Excel) и `report.md` с пояснениями и агрегатами.
Вложенные списки/объекты в CSV — JSON. Настоящие файлы содержат приватную разметку:
не публиковать даже при успешной проверке.

## Проверка и свидетельства TDD

Циклы выполнялись вертикально: тест → наблюдаемый RED → минимальная реализация → GREEN,
затем следующая функциональность. Первая проверка `test_supported_timestamps`:
`Ran 1 test`, `FAILED (failures=1)`, причина `timestamp parser is not implemented`;
после реализации тот же запуск: `Ran 1 test`, `OK`.

Далее отдельно наблюдались RED/GREEN для загрузчика CSV/XLSX, учёта abstention,
аннотаций и взаимно-однозначного сопоставления, angle holdout, полноценного CLI/файлов
отчёта, строгой валидации API, unknown type/SLA и частичной разметки типов.
Регрессионный тест на частичные типы сначала обнаружил precision `2.0`, после исправления
получает `1.0` при явном знаменателе `1`.
Все тестовые входы искусственные и не являются оценкой реальной модели.

Настоящий аудит отдельно проверяет только наличие/метаданные и состав разметки;
он не подтверждает качество распознавания. Для реального `score` необходимы реальные
предсказания разрешённого локального пайплайна. Без ручной разметки типов/ракурсов нельзя
заявлять качество по категориям или на отложенном ракурсе.
