# Задача команде: event gold без новой съёмки

Новые видео не снимаем. Используем существующие **42 файла / 40 уникальных development-содержимых**. Алпамыс и Олжас делают два независимых просмотра и adjudication; Агыбай фиксирует последующий эксперимент. Нужны разметка и контрасты, без новой модели, GPU или приложения. Это план работы, не полученный результат.

## Три типа первого frontier

Названия сверены с [actions](../ml/vlm/action_backend.py) и [allowlist](../ml/vlm/discovery_policy.py). Остальные четыре allowlisted-типа пока не получают exhaustive gold.

| Action / type_id | Что должно быть видно | Контраст либо `unknown` |
| --- | --- | --- |
| `key_remains_in_safe_lock_after_departure` / `key_left_in_safe_lock` | Различимый ключ в замке идентифицируемого сейфа, уход работника от сейфа, затем ключ остаётся; тот же предмет прослеживается. | Извлечение ключа перед уходом — контраст. Блик/ручка, неидентифицированный шкаф, мелкий объект или скрытый уход — `unknown`, пока нет достаточного свидетельства. Box детектора не удостоверяет сейф. |
| `cashier_places_removed_outerwear_on_cashdesk` / `personal_items_on_desk` | Работающий за местом человек держит уже снятую верхнюю одежду, кладёт на свой рабочий стол, одежда остаётся. Само снятие с тела видеть необязательно. | Сумка посетителя, одежда на стуле или действие другого участника — контрасты после проверки. Неразличимые предмет, роль или стол — `unknown`. |
| `food_or_drink_actually_consumed` / `food_or_drink_at_workplace` | Реальный укус еды либо питьё из различимой чашки у рта человеком за рабочим местом. | Стоящая чашка, удерживание ёмкости без питья, касание лица — проверяемые контрасты. Скрытые рот/предмет/контакт — `unknown`. |

Это физические наблюдения, не правовой вердикт. Роль не выводится из одежды; пропуск процедуры между кадрами не доказывает её отсутствия. Отсутствие primary-метки не делает эпизод отрицательным.

## Исполнимый порядок

1. До нового model run зафиксировать manifest **8 уникальных видео** из согласованного существующего пилота. Смотреть оригиналы целиком, отмечая все эпизоды трёх типов и обычные контрасты, а не только organiser peak или найденный VLM фрагмент. Использовать существующую локальную страницу `var/manual-angle-review-2026-10-17/index.html`, покадровый проигрыватель и CSV/JSON; новый review UI не нужен.
2. Сдать **24 coverage-записи**: 8 источников × 3 типа. Два просмотра — 16 reviewer passes, не 16 независимых видео. Реальные counts positives/contrasts/unknown определяются просмотром, не задаются квотой. Первый подход ориентировочно 2–4 часа, без обещания закончить весь набор.
3. Затем расширить процесс на все **40 содержимых / 120 coverage-записей**. Если просмотрен только интервал, полнота относится лишь к нему и этим трём типам; остальное `unreviewed`, а не background. Даже полный проход не делает gold остальных типов exhaustive.
4. Искать matched hard negatives в существующем материале по отличию предмета, роли, контакта или порядка действий. Записать совпадения и различия контекста. Если подходящей пары нет, сообщить об этом; не называть похожие фрагменты строго matched. Контраст конкретного типа не делает весь положительный ролик чистым.

## Что сдать локально в ignored `var/`

- `coverage.csv`: source ID, actual SHA256, aliases, известные session/source/camera groups либо `unknown`, тип, просмотренные границы, полнота для типа, reviewer/date. Сохранить версии/hash исходных primary truth.
- `episodes.jsonl`: episode ID, источник, тип, `observed_positive / observed_contrast / unknown`, start/решающий peak/end, видимость предмета/контакта/ухода, локальные actor/object track IDs, continuity `yes/no/unknown`. Неизвестные границы — `null` с кодом причины; peak не выдумывать. Для отдельного видимого приёма пищи допустим `start=peak=end`.
- `adjudication.csv`: оба независимых решения, код разногласия, согласованное решение либо оставшийся `unknown`. Второй человек проверяет также контрасты и неизвестность; исходные решения сохраняются.
- Coded/numeric summary: просмотренное покрытие, counts, ошибки границ и нерешённые случаи. Кадры, свободные описания и per-content model responses не добавлять в Git.

Для известных времён проверить `reviewed_start ≤ start ≤ peak ≤ end ≤ reviewed_end` и границы файла. Зафиксировать video-relative timebase; нынешний `Frame(t,t)` не называть actual PTS. Organiser labels и `kb/annotations.csv` не менять: episode gold — отдельный overlay с provenance, спор с первичной меткой записывается отдельно.

## Группировка и критерий готовности

Оригинал, точные дубли, crops/windows и известные связанные записи всегда остаются в одной source group и одном split. Для производного сохраняются parent SHA и source-time mapping. Они **не увеличивают N**: пилот остаётся 8 содержимыми, весь набор — 40. Crop не заменяет просмотр исходника; неразличимый мелкий объект остаётся `unknown`.

Все 40 уже development. Новый split, второй reviewer или crop не создают независимый bank-camera holdout. Неизвестные session/camera IDs не подменять hashes/именами файлов. Заранее выделенные контрольные группы не участвуют в prompt/threshold/sampling tuning; после подбора по их результатам они тоже development. Изоляция камер при неизвестных связях не доказана.

MVP готов при полном manifest 8 содержимых и aliases, 24 coverage-записях, двух решениях/adjudication по эпизодам, контрастам и unknown, проверенных границах/enum. Нехватка различимых ключей или подходящих negatives — явный пробел данных, а не повод ослабить критерий. Готовность разметки не требует положительного результата модели.

После фиксации source/model/prompt/sampling/gates отдельно считать подтверждение positives, добавления на human-confirmed контрастах, ответы на unknown и same-event type+time. Ошибка/timeout/unknown не являются отрицательной меткой. Event precision допустим только для объявленных типов в полностью размеченных интервалах с явным знаменателем; primary-only labels этого не обеспечивают. Результат не доказывает новое банковское окружение или юридическое нарушение.

Внешние источники из исследования необязательны: сначала official URL/revision, лицензия именно данных и доступные object/contact labels. Крупные datasets/weights не скачивать. Общий action dataset и реквизит не являются bank-domain gold; для этой задачи внешние данные не нужны.
