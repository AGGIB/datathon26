# Эксперименты после исследования Алпамыса

Исходники: `result of research.zip` SHA256 `d04ca0cca1ce5341b7c971e40391a56f59e9b77f6de1b1e767299041af85bd4a`; `-dt-main.zip` SHA256 `319975f48393aa0b71cdc2d8ea14851532d384c5d0291c36717095318010d697`. Вложенный research ZIP во втором архиве совпадает с первым. Шесть обзоров прочитаны и сопоставлены с исходниками проекта; чужой код из архива не исполнялся.

## Что переносим из исследования

Архив содержит отдельный CUDA-проект ForteVision: Qwen3-VL-2B BF16/SDPA, последовательный PyAV decode с исходными PTS, оконный batch inference, три значения визуальных фактов и отдельные условия применимости правил. После первого прохода 31/42 и повтора 11 невалидных ответов технически обработаны 42/42 файлов. `semantic_accuracy_evaluated=false`: это не подтверждённое качество типов и не сравнение с нашим V5. Заявленные 119 тестов и времена RTX 5070 также не являются замерами M4.

Полезны ограниченные временные окна, реальные PTS, различение неизвестного факта и отрицания, отдельная оценка визуальной информации. Нормативный каталог, CUDA-окружение и сервис целиком не заменяют проверенную командную интеграцию.

| Направление из обзоров | Решение для первого эксперимента |
| --- | --- |
| Увеличение VLM / другой общий prompt | Уже проверено 4B→9B: потерянный тип ключа не вернулся. Новых весов не загружаем. |
| Объектное представление | Проверить общий контекст и увеличенную рабочую зону из того же исходного кадра. |
| Temporal/state-change reasoning | Следующая гипотеза: независимые before/contact/after witnesses и собственные контрастные последовательности. Изменение порядка не обязано менять статическое состояние ключа. |
| LoRA / temporal head | Отложить до полной event-разметки и разделения настоящих съёмочных сессий. Primary-only метки не делают остальное время background. |
| Внешние action/anomaly datasets | Проверять конкретную лицензию данных и соответствие примитива; общий action label не является банковским gold. В первом эксперименте не используются. |

В обзорах есть ошибки: Qwen2.5-VL-3B нельзя считать Apache-2.0 по лицензии другого размера; лицензия кода Ego4D не равна лицензии видео; стандартный COCO checkpoint не содержит классов hand/banknote/key/stamp. Исправления отмечены и в собственном `research_decisions.md` Алпамыса. Примеры проверенных первичных источников: [Qwen LICENSE](https://huggingface.co/Qwen/Qwen2.5-VL-3B-Instruct/blob/main/LICENSE), [Ego4D access](https://ego4d-data.org/docs/start-here/), [RT-DETR classes](https://huggingface.co/PekingU/rtdetr_r50vd/blob/main/config.json).

Объектное представление мотивируется [SAVi/SAVi++](https://github.com/google-research/slot-attention-video); временные контрастные проверки — [TempCompass](https://github.com/llyx97/TempCompass). Это основания для собственных гипотез, а не обещание переноса опубликованных результатов. Код, веса и корпуса этих работ в эксперимент не добавляются.

## Зафиксированный первый тест: пространственная информация

Цель — сохранить правильные типы V5 (11/21) и joint (5/21), не добавить событий на 19 известных чистых и получить хотя бы одно дополнительное совпадение. Возврат потерянного ключа и сохранение всех трёх прежних улучшений V4 учитываются явно. Все исходные CV-события должны сохраниться точно; confidence остаётся 0,95.

На одном M4 и существующем pinned Qwen3.5-4B сравниваются два представления verifier:

1. **Original:** исходные кадры и неизменный compact verifier.
2. **Workspace:** 640×352, слева полный контекст 192×352, справа рабочая зона 448×352. Два участка показывают один кадр, момент, человека и предмет; повторное изображение не является независимым подтверждением.

Времена, порядок, atoms/schema, gate, model и число обращений одинаковы. ROI определяется только геометрией perception/scene; выбранное действие, тип, gold и ID видео в выборе не участвуют. Геометрическое предложение не удостоверяет, что объект действительно является сейфом. При недостоверной геометрии или отсутствии увеличения сохраняются исходные кадры; истечение deadline прерывает optional вызов. Модель сама проверяет видимый предмет и отношения.

Первый screen восстанавливает **14 сохранённых V4 proposals в 14 окнах** всех 40 уникальных видео. В каждом arm выполняется до 14 новых verifier calls; proposal attempts являются replay и считаются отдельно. Точные дубли переиспользуют результат. Это условный A/B-тест, **не свежая регенерация полного pipeline**. Модельные ответы и изображения остаются в ignored `var/`.

Проверяются реальные processor grids/vision tokens: одинаковый размер площади сам по себе не устанавливает равенство вычислений. Startup измеряется отдельно; warm stage включает composition, decode, cached proposal, verification и merge вместе, без отдельной разбивки этих операций. Один worker работает последовательно; deadline и общий cap четырёх логических обращений на видео сохраняются.

Если candidate сохраняет все правильные primary/joint совпадения контрольного arm и прежнего V5, не даёт clean additions и добавляет хотя бы одно правильное primary/joint совпадение, он переходит в **fresh full40** с новым выполнением proposals и verification. Иначе фиксируется отрицательный результат без включения в pipeline. Пороги по результатам screen не меняются.

## Ограничения оценки

Исходная точка — V5: video precision 16/(16+5)=76,2%, primary 11/21, joint 5/21; пять CV FP остаются. Задача screen — новые добавления VLM, не удаление исходных CV-событий. Дополнительные эпизоды положительных видео не становятся правильными автоматически; event precision без полного inventory не вычисляется.

Эти 40 видео многократно использованы для разработки. Новый ракурс, независимая калибровка и полный live-job прирост не доказаны. Производственный default остаётся off. Измеренные результаты приведены ниже.

## Пространственный screen: результат

Оба arm завершены: 42 файла / 40 уникальных, по 52 сохранённых proposal attempts и **14 реальных verifier calls**, два точных дубля без повторного inference. Для workspace геометрия доступна на 33/42 файлах; остальные используют исходные кадры. На синтетических входах реальный pinned processor подтвердил 220 vision tokens/frame для обоих форматов. Политика и source заморожены в `f471d06`.

**Улучшения не получено:** оба варианта дают primary **11/21**, joint **5/21**, TP16/FP5/FN5/TN14, новых событий на чистых **0**. Все 42 результата каждого arm совпали с replay настоящих discovery/runtime gap/slots/assembly; полные CV Candidate сохранены. Независимый integrity audit прошёл **72/72**, включая pins, геометрию, source-time mapping, дубли и cached/actual accounting. Ошибок формата verifier нет. Дополнительный объём деталей не вернул потерянный ключ; gate нового прироста не пройден, fresh full40 для spatial-кандидата не запускается.

Артефакты: `var/runs/vlm_spatial_{original,workspace}_v1.{json,screening-details.json,selection-replay.json}`, `var/runs/vlm_spatial_v1.integrity.{json,md}`. Это условные model experiments, не свежая генерация proposals и не новый ракурс.

Измеренное warm дополнение с сохранённым первым проходом: 130,91 с суммарно для original и 207,68 с для workspace на 40 уникальных видео; startup 5,56/6,53 с отдельно. Это frame preparation + cached proposal + verification + merge, без CV/evidence и чтения geometry cache. Равные vision tokens не гарантируют равную задержку. В историческом geometry report `source_frame_index` означал позицию во входе verifier; опубликованный интерфейс уточняет имя до `supplied_frame_index` и не заявляет реальный номер кадра контейнера.

## Следующий тест: поиск временных witnesses

Проверка только исходных proposal anchors может пропускать промежуточные наблюдения. Проверяем гипотезу: нейтральный inventory всех уже выбранных кадров окна позволяет искать достаточные witnesses без привязки к исходным anchors.

Новый opt-in эксперимент запрашивает нейтральные физические факты **для всех 12 уже выбранных кадров окна**, без новой выборки или decode. Тип, действие, confidence и исходные proposal anchors не передаются verifier. Локальный код ищет упорядоченную тройку `before < peak < after`, удовлетворяющую прежнему строгому physical predicate и continuity; выбирается кратчайшая подтверждённая тройка, при равенстве — более ранняя. Приём пищи допускает отдельный полностью подтверждённый peak. Положительный результат заново локализуется на временных метках выбранных кадров; выдавать новые witnesses за старые anchors нельзя.

Исходная шкала здесь **cv_index_fps**, не фактически декодированные PTS: текущий owner не хранит их. Реализация PyAV Алпамыса показывает направление дальнейшего улучшения, но её PTS-контракт не приписывается нашим текущим Frame. В диагностическом backend один eligible proposal на окно; несколько дают отказ вместо произвольного назначения actor/object. Сохраняются unknown, исходный confidence, owner gate 0,95, общий cap4 и deadline. Бюджет генерации 768 токенов фиксируется отдельно; большее число кадров не выдаётся за сравнение при равных вычислениях.

Проверяются те же 14 сохранённых proposal windows, без ROI-преобразования. До вызовов фиксируются pins и gates: точное сохранение CV, всех правильных V5 primary/joint hits, clean additions 0 и хотя бы одно новое правильное совпадение. Только успешный screen допускает fresh full40. Это отдельная гипотеза после отрицательного spatial-теста; его protocol и результат не меняются.

## Временной screen: результат и решение

Замороженный source `69e3b7d1bdb8eb49db5b59afec22f43971d52343`; preregistration SHA256 `951962df54cbdf692440407bbfc50a4401957b5758f5780c05f333c6f2af6ced`. Завершены 42 файла / 40 уникальных содержимых: 52 cached proposal attempts, **14 новых полных inventories**, два повторных использования точных дублей. Все 14 inventories валидны; malformed/runtime errors нет. По неизменённым predicates временных witnesses не найдено, новых findings/additions **0**. Это отказ от подтверждения, а не 14 доказанных отрицательных видеособытий.

| Вариант | TP / FP / FN / TN | Precision по видео | Primary type | Joint ±2 с | Новых событий на чистых |
| --- | --- | --- | --- | --- | --- |
| Замороженный CV | 15 / 5 / 6 / 14 | 75,0% | 9/21 | 4/21 | 0 |
| V5 / spatial original / workspace | 16 / 5 / 5 / 14 | 76,2% | 11/21 | 5/21 | 0 |
| Temporal witness screen | 15 / 5 / 6 / 14 | 75,0% | 9/21 | 4/21 | 0 |

**NO-GO:** против V5 и spatial original потеряны два правильных primary type hits и один joint hit; новых совпадений нет. Из трёх прежних V4 type gains сохранено 0/3. Условие нулевых новых clean additions выполнено, но оно не компенсирует потерю находок. Fresh full40 для этого кандидата **не запускается**, пороги не меняются. Последний подтверждённый полный V5 результат остаётся отдельной отправной точкой; temporal-вариант его не заменяет.

Независимые numeric engines совпали на шести arms; отдельный postflight подтвердил protocol/source/runtime/model/input pins и call accounting. CPU replay настоящего отбора дал точное совпадение всех 42 outputs и сохранение полных CV Candidate. В temporal output нет новых Candidate: перенос времени реального добавления этим replay **не упражнён**, его функциональные проверки остаются synthetic. Private артефакты: `var/runs/vlm_temporal_v1.{json,screening-details.json,paired.json,integrity.json,selection-replay.json}`, `vlm_temporal_v1.numerical-review.json`, `vlm_temporal_v1.preregistered-review.json`.

Warm screen с сохранённым первым проходом: 561,07 с суммарно, среднее 14,03 с и максимум 57,87 с на 40 уникальных видео; startup 5,25 с отдельно. Это не полный fresh inference, стоимость CV/evidence или SLA сервиса. На source `69e3b7d` полный suite: **2329 passed**, включая реальный RT-DETR integration test; Ruff clean. Тесты подтверждают реализацию, не качество распознавания.

## Что проверять дальше

Два отрицательных теста не доказывают ни невозможность распознавания, ни отсутствие событий. Они не подтвердили пользу общего ROI и нейтрального полного inventory на текущих кадрах. Следующий опыт должен отдельно установить, попадает ли решающее действие в кадры и различим ли предмет; перестановка prompt или ослабление unknown без такой проверки не устраняют эту неопределённость.

Для команды обновлены [ближайшие задачи](team-next-tasks.md): фактические PTS с привязкой evidence; human episode gold и matched hard negatives; пригодность и права внешних данных. SigLIP этап A уже завершён отрицательно через PR #45; вместо повторного обучения подготовлен локальный numeric frozen CV export для существующего matched AND/OR comparison. Он содержит 42 записи / 40 SHA / 24 события и проходит настоящий `diagnostic_io.load_frozen_cv`; это не повторная проверка SigLIP caches и не новый OOF результат. Кадры, веса, embeddings, per-content ответы и архивы в Git не входят.

Новая съёмка недоступна. Исполнимый следующий шаг — [разметка эпизодов и контрастов существующих записей](vlm-data-without-recording.md); производные окна/crops не увеличивают число независимых источников.
