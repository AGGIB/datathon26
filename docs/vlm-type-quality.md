# Локальная VLM: определение типов и проверка качества

`ml.vlm.verify` оставляет исходные CV-кандидаты без изменений. Для поиска пропущенных типов добавлен отдельный `ml.vlm.discovery`: он рассматривает упорядоченные кадры и предлагает новые события из явного подмножества проверенного каталога. Модель не получает имя видео, метку класса, авторскую аннотацию, наблюдения CV или юридические цитаты.

Первый эксперимент использует Qwen3-VL-4B-Instruct-4bit на физическом Apple M4 с 16 GB памяти. Точный checkpoint, лицензия Apache-2.0 и SHA256 перечислены в [licenses-ml.md](licenses-ml.md) и [checkpoints-ml.json](checkpoints-ml.json). MLX работает в отдельном окружении; основной CV runtime не обновляется.

## Поведение

Фиксированная политика `positive_actions_uniform_halves_12_v2` выбирает 12 кадров по всему ролику длительностью до 30 секунд либо по 12 кадров из двух половин более длинного ролика. Кадры извлекаются одним проходом `ml.video.frames_at`, с той же шкалой index/FPS, что у CV. Все вызовы разделяют один абсолютный deadline и максимум два обращения к модели. По умолчанию рассматриваются семь типов с положительно наблюдаемым физическим действием. Отсутствие процедурной проверки по разреженным кадрам не доказывается; такие типы исключены из этой политики.

MLX worker принимает только локальные файлы, отключает Hugging Face/Transformers сеть и `trust_remote_code`. Запуск модели происходит явно до обработки заданий. Worker можно завершить по таймауту; после сбоя он автоматически не перезапускается. Конкурирующий вызов получает отказ без ожидания занятой модели.

JSON Schema ограничивает форму ответа, типы и времена показанных кадров. Постпроверка дополнительно требует последовательных границ события и наблюдений на этих границах. Это проверка структуры, а не визуальной истинности. Самооценка confidence модели пока не откалибрована.

CV-кандидаты сохраняются. Добавления используют свободные места в ответе из пяти событий; близкая находка того же типа не может изменить исходный CV-эпизод через объединение. При недоступной модели, недостатке времени, неполных кадрах или ошибке JSON возвращается CV-результат. Юридический текст формируется только сборщиком из KB, не моделью. T04 без проверенной нормы остаётся в CV; discovery явно сообщает его недоступность.

## Воспроизведение

Подготовка окружения выполняется отдельно, пока сеть разрешена:

```bash
uv venv --python .venv/bin/python var/venvs/vlm-mlx
uv pip install --python var/venvs/vlm-mlx/bin/python -r requirements-ml-vlm-mlx-lock.txt
```

Публичные веса ревизии `2fd8dacbdb8f1e54b8c005f081ec5bf79c56376b` должны быть заранее скачаны в `models/Qwen3-VL-4B-Instruct-4bit`; загрузок из inference-кода нет. Проверить SHA256 `model.safetensors`: `90eeb02604181dbcccd0a30a1f550a4a8928ca7dcbee4aee1449239306cfdfca`.

В этом конкретном MLX snapshot также лежит устаревший `model.safetensors.index.json`, ссылающийся на два отсутствующих исходных PyTorch-shard. Он не описывает проверенный единый квантованный файл. Исключить этот индекс при подготовительной загрузке (`ignore_patterns=["model.safetensors.index.json"]`) либо сохранить его отдельно вне runtime-каталога. В локальной подготовке исходный индекс архивирован с SHA256 в `var/runs/qwen3_vl_preparation_receipt.json`; веса не менялись. Общая проверка целостности других моделей остаётся строгой.

Пробный прогон читает готовые CV-ответы, но не метки truth:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m ml.tools.vlm_type_probe \
  --model models/Qwen3-VL-4B-Instruct-4bit \
  --python var/venvs/vlm-mlx/bin/python \
  --baseline var/runs/vlm_cv_baseline_af24b8b.json \
  --out var/runs/vlm_action_example.json \
  --action-contrast \
  --only X-1,X-3,X-16,X-17,X-40,X-43,X-44,X-46
```

`--out` должен быть новым JSON под игнорируемым `var/`. Результат и соседний `.audit.json` фиксируют SHA256 медиа, всех файлов модели, исходников и версий runtime. Одинаковые байты видео не запускают повторный inference. Сбой VLM отмечается `vlm_error`, сохраняя пригодный к оценке CV-ответ. Время probe включает тёплый VLM и чтение кадров; CV берётся из сохранённых ответов, а startup указан отдельно. Это не измерение полного production SLA.

Команда ниже предназначена для экспериментального локального smoke. Качество для пользовательских запросов не подтверждено; по умолчанию discovery выключен. Опциональная интеграция с К2 включается только явно при запуске сервиса:

```bash
ML_VLM_DISCOVERY=1 \
ML_VLM_MODEL="$PWD/models/Qwen3-VL-4B-Instruct-4bit" \
ML_VLM_PYTHON="$PWD/var/venvs/vlm-mlx/bin/python" \
PIPELINE=real WORKERS=1 \
.venv/bin/uvicorn --factory backend.app.main:app_from_env --host 127.0.0.1 --port 8000
```

`ml.pipeline.preload()` выполняет явный startup. Без него модель не поднимается внутри video job. По умолчанию discovery выключен; отдельная проверка нескольких параллельных CV/MLX заданий на общей памяти пока не проведена.

## Данные и смысл метрик

Прежние 42 файла — 40 уникальных видео, 21 положительное и 19 чистых. Они уже использовались при разработке CV. Базовый результат: первичный тип 9/21, тот же тип и таймкод в ±2 секунды 4/21; TP15, FP5, FN6, TN14. Для VLM используется заново вычисленный calibrated CV replay `vlm_cv_baseline_af24b8b.json`, совпадающий с сохранённой калибровкой main. В нём у X39 исключён старый ложный safe-эпизод; бинарные показатели от этого не меняются.

На этом наборе можно измерять изменение качества разработки. Авторские аннотации задают первичный тип; дополнительные находки в положительном видео требуют отдельной проверки и не становятся автоматически подтверждёнными или ложными. Для известных чистых видео все добавленные события учитываются как ложные добавления. Отдельно считаются тип без времени и **то же событие с правильным типом и временем**; совпадение этих двух признаков у разных событий не засчитывается совместным попаданием.

Новой съёмки у пользователя пока нет. Публичный поиск казахстанских банковских видео нашёл [запись Alfa-bank в материале Tengrinews](https://tengrinews.kz/crime/video-ogrableniia-alfa-banka-v-almaty-pokazali-v-sude-326422/) и [сюжет 24KZ](https://24.kz/ru/tv-projects/dezhurnaya-chast/754527-10-tysyach-dollarov-edva-ne-ushli-moshennikam-pensionerku-spasla-kassir-banka-dezhurnaya-chast). Подтверждённого разрешения повторного использования и ручной gold-разметки нет; видео не скачивались и в benchmark не включены. Проверка нового ракурса остаётся незавершённой. Условия подготовки независимого набора и его метрики описаны в [angle-holdout.md](angle-holdout.md).

Локальная форма `var/manual-angle-review-2026-10-17/index.html` позволяет человеку назначить реальные камеры и группы съёмки для 40 уникальных старых видео. Разметка камер сама по себе не превращает development-видео в новый holdout. Форма и кадры остаются локальными.

## Development-пилоты Qwen3-VL

Одни и те же восемь уникальных клипов: пять положительных и три известных чистых. В этом подмножестве CV имеет TP2/FP0/FN3/TN3, основной тип 0/5 и совместное попадание того же события по типу и времени ±2 с — 0/5. Это выбранные трудные примеры, а не оценка полного набора или нового ракурса.

| Вариант | Основной тип | Тип + время ±2 с | Новых событий на чистых | TP / FP / FN / TN |
| --- | ---: | ---: | ---: | --- |
| V1: прямой выбор из 11 типов | 2/5 | 0/5 | 3 на 3 клипах | 4 / 3 / 1 / 0 |
| V2: семь positive-action типов | 2/5 | 1/5 | 6 на 3 клипах | 4 / 3 / 1 / 0 |
| V3: физические и обычные действия, индексы сначала | 0/5 | 0/5 | 0 | 2 / 0 / 3 / 3 |
| V4: действие сначала, поиск по всем кадрам | 1/5 | 0/5 | 0 | 3 / 0 / 2 / 3 |

V1 и V2 отклонены из-за ложных добавлений на всех трёх чистых примерах. V3 не добавил ни одного события. V4 добавил один правильный первичный тип (еда/напиток), но его пик отличается от первичной метки на 2,8 с; совместного попадания нет. Ноль ложных добавлений на трёх клипах не устанавливает precision на 19 чистых или независимом наборе. Дополнительные события положительных клипов не считаются автоматически подтверждёнными.

Все четыре прогона завершились 8/8, сохранили исходные CV-события без изменения и прошли проверку неизменности кода/KB. V4 использовал восемь model calls: тёплое дополнение в среднем 21,45 с, максимум 27,06 с; CV replay, startup и полный evidence pipeline в эти времена не входят. Числовые отчёты сохранены локально под `var/runs/vlm_pilot_v{1,2,3,4}.comparison.json`; приватные ответы и кадры не входят в Git.

`--action-contrast` у probe включает экспериментальный `physical_action_search_v4`: он различает физические целевые действия и обычные альтернативы, затем сопоставляет только разрешённые действия с проверенным каталогом. Сгенерированные фазовые описания являются шаблонным переводом выбранного действия, а не независимым визуальным подтверждением. Owned opt-in runtime использует тот же action decoder V4; backend injection остаётся прямым тестовым seam. Профиль **не утверждён по качеству и остаётся выключенным по умолчанию**. Новые рабочие задачи перечислены в [vlm-next-tasks.md](vlm-next-tasks.md).


Отдельный V4-прогон всех известных чистых видео завершён: 20 файлов / 19 уникальных содержимых, 0 новых событий и 0 ошибок enhancement. Все исходные CV-события сохранены; прежние CV FP5/TN14 не изменились. Выполнено 28 model calls, один точный дубль использовал сохранённый inference. Это проверка ложных добавлений на старом development-наборе, не доказательство нулевого FP системы. Отчёт: `var/runs/vlm_clean_v4.comparison.json`. Его source fingerprint отличается от восьмиклипового пилота (добавлена поддержка Qwen3.5 и явный non-thinking template); cohorts не объединяются в один замороженный полный benchmark.

Ближайшие параллельные задачи с владельцами: [team-next-tasks.md](team-next-tasks.md); отдельная задача Нурхану — [team-ml2-next-task.md](team-ml2-next-task.md). ## Полный Qwen3.5 V4: результат и решение

Замороженный source `347a0170ac23aa4167ff4ab9fa93060c0c57325b`, те же 42 файла / 40 уникальных содержимых. Все 42 завершены без runtime enhancement errors; 52 реальных вызова, два точных дубля использовали сохранённый результат. В трёх вызовах строгая проверка отклонила целевое действие без наблюдаемого порядка (`action_order_unobserved`); эти окна дали отказ от добавления, а не ошибку выполнения всего ролика. Проверены реальные content hashes, fingerprint конфигурации, все ML/KB-байты snapshot и сохранение каждого исходного CV-события. Независимая числовая проверка прошла 31/31 проверок.

Два чистых видео впервые стали ложноположительными; на других трёх чистых уже были ошибки CV. Прибавка правильных первичных типов не является доказательством полного event precision.

Тёплое дополнение: mean 39,51 с, median 30,55 с, max 75,91 с на 40 уникальных видео; startup 3,86 с отдельно, I/O двух reused copies — mean 0,11 с. CV и evidence в эти времена не входят. Основной результат: `var/runs/vlm_qwen35_full_v4.comparison.json`; независимая проверка — соседний `.independent-review.json`.

Дополнительно выполнен **условный replay выбора событий**: существующие CV-кандидаты восстановлены из доверенного локального cache и точно совпали с calibrated baseline на всех 42 файлах. Все 14 сохранённых findings восстановлены точно по фиксированным фазам action decoder; применены настоящие discovery overlap gates, `augment_types` и `assemble.select`, без нового inference/decode/evidence. На этом прогоне выбор событий совпал с упрощённым probe на всех семи заранее заданных общих порогах.

Это настройка на development-ответах, не независимая калибровка. Условный replay не проверяет wall-clock deadline, доступность модели или пригодность evidence в настоящем job. Его локальные артефакты — `var/runs/conditional_selection_replay.{json,md}`.

Следующая необходимая работа — независимый human inventory действий, участников и предметов; затем сравнение представления движения и контекстных видов. Переподбор prompts на тех же 40 видео не заменит новую съёмку и независимую проверку. На новом ракурсе качество по-прежнему не измерено.


## Контроль native-video представления движения

Отдельный синтетический контроль использовал два простых пути красного круга: движение вправо и движение вправо с последующим разворотом влево. Для каждого сравнены 12 stills, native-video из 24 повторов тех же 12 кадров и native-video из 24 настоящих последовательных кадров. Во всех вариантах проверены 2640 визуальных токенов, реальные индексы известного синтетического источника 4 FPS и отсутствие дополнительного decode/sampling/URL-вызовов. Модель загружалась одна, вызовы выполнялись последовательно.

Все шесть вызовов завершились, направление правильно выбрано в 3/6: каждый формат распознал движение вправо, каждый перепутал название направления разворота. Результат 1/2 в каждом формате не подтверждает преимущество native-video. Это малый контроль выбора direction enum; он не устанавливает причину ошибок банковских действий и не доказывает отсутствие понимания движения. Продуктовый видеовход не менялся. Артефакт: `var/runs/native_video_motion_control_qwen35_v1.json`.

Для будущего реального native-video опыта требуются фактически декодированные source indices и FPS, а также явный контракт временных групп. Текущий `Frame(timestamp_s,path,pts_s)` этого не хранит; округлённый запрошенный timestamp и EOF fallback нельзя выдавать за фактический source index. Это отдельная задача до сравнения на реальных клипах.
