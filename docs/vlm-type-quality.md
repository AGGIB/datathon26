# Локальная VLM: определение типов и проверка качества

`ml.vlm.verify` оставляет исходные CV-кандидаты без изменений. Для поиска пропущенных типов добавлен отдельный `ml.vlm.discovery`: он рассматривает упорядоченные кадры и предлагает новые события из явного подмножества проверенного каталога. Модель не получает имя видео, метку класса, авторскую аннотацию, наблюдения CV или юридические цитаты.

Первый эксперимент использует Qwen3-VL-4B-Instruct-4bit на физическом Apple M4 с 16 GB памяти. Точный checkpoint, лицензия Apache-2.0 и SHA256 перечислены в [licenses-ml.md](licenses-ml.md) и [checkpoints-ml.json](checkpoints-ml.json). MLX работает в отдельном окружении; основной CV runtime не обновляется.

## Поведение

Фиксированная политика `positive_actions_uniform_halves_12_v2` выбирает 12 кадров по всему ролику длительностью до 30 секунд либо по 12 кадров из двух половин более длинного ролика. Кадры извлекаются одним проходом `ml.video.frames_at`, с той же шкалой index/FPS, что у CV. Все вызовы разделяют один абсолютный deadline и максимум два обращения к модели. По умолчанию рассматриваются семь типов с положительно наблюдаемым физическим действием. Отсутствие процедурной проверки по разреженным кадрам не доказывается; такие типы исключены из этой политики.

MLX worker принимает только локальные файлы, отключает Hugging Face/Transformers сеть и `trust_remote_code`. Запуск модели происходит явно до обработки заданий. Worker можно завершить по таймауту; после сбоя он автоматически не перезапускается. Конкурирующий вызов получает отказ без ожидания занятой модели.

JSON Schema ограничивает форму ответа, типы и времена показанных кадров. Постпроверка дополнительно требует последовательных границ события и наблюдений на этих границах. Это проверка структуры, а не визуальной истинности. Самооценка confidence модели пока не откалибрована.

CV-кандидаты сохраняются. Добавления используют свободные места в ответе из пяти событий; близкая находка того же типа не может изменить исходный CV-эпизод через объединение. При недоступной модели, недостатке времени, неполных кадрах или ошибке JSON возвращается CV-результат. Юридический текст формируется только сборщиком из KB, не моделью. T04 без проверенной нормы остаётся в CV; discovery явно сообщает его недоступность.

## Воспроизведение

Подготовка окружения выполняется отдельно, пока сеть разрешена:

```bash
uv venv --python .venv/bin/python var/venvs/vlm-mlx
uv pip install --python var/venvs/vlm-mlx/bin/python -r requirements-ml-vlm-mlx-lock.txt
```

Публичные веса ревизии `2fd8dacbdb8f1e54b8c005f081ec5bf79c56376b` должны быть заранее скачаны в `models/Qwen3-VL-4B-Instruct-4bit`; загрузок из inference-кода нет. Проверить SHA256 `model.safetensors`: `90eeb02604181dbcccd0a30a1f550a4a8928ca7dcbee4aee1449239306cfdfca`.

В этом конкретном MLX snapshot также лежит устаревший `model.safetensors.index.json`, ссылающийся на два отсутствующих исходных PyTorch-shard. Он не описывает проверенный единый квантованный файл. Исключить этот индекс при подготовительной загрузке (`ignore_patterns=["model.safetensors.index.json"]`) либо сохранить его отдельно вне runtime-каталога. В локальной подготовке исходный индекс архивирован с SHA256 в `var/runs/qwen3_vl_preparation_receipt.json`; веса не менялись. Общая проверка целостности других моделей остаётся строгой.

Пробный прогон читает готовые CV-ответы, но не метки truth:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m ml.tools.vlm_type_probe \
  --model models/Qwen3-VL-4B-Instruct-4bit \
  --python var/venvs/vlm-mlx/bin/python \
  --baseline var/runs/vlm_cv_baseline_af24b8b.json \
  --out var/runs/vlm_action_example.json \
  --action-contrast \
  --only X-1,X-3,X-16,X-17,X-40,X-43,X-44,X-46
```

`--out` должен быть новым JSON под игнорируемым `var/`. Результат и соседний `.audit.json` фиксируют SHA256 медиа, всех файлов модели, исходников и версий runtime. Одинаковые байты видео не запускают повторный inference. Сбой VLM отмечается `vlm_error`, сохраняя пригодный к оценке CV-ответ. Время probe включает тёплый VLM и чтение кадров; CV берётся из сохранённых ответов, а startup указан отдельно. Это не измерение полного production SLA.

Команда ниже предназначена для экспериментального локального smoke. Качество для пользовательских запросов не подтверждено; по умолчанию discovery выключен. Опциональная интеграция с К2 включается только явно при запуске сервиса:

```bash
ML_VLM_DISCOVERY=1 \
ML_VLM_MODEL="$PWD/models/Qwen3-VL-4B-Instruct-4bit" \
ML_VLM_PYTHON="$PWD/var/venvs/vlm-mlx/bin/python" \
PIPELINE=real WORKERS=1 \
.venv/bin/uvicorn --factory backend.app.main:app_from_env --host 127.0.0.1 --port 8000
```

`ml.pipeline.preload()` выполняет явный startup. Без него модель не поднимается внутри video job. По умолчанию discovery выключен; отдельная проверка нескольких параллельных CV/MLX заданий на общей памяти пока не проведена.

## Данные и смысл метрик

Прежние 42 файла — 40 уникальных видео, 21 положительное и 19 чистых. Они уже использовались при разработке CV. Базовый результат: первичный тип 9/21, тот же тип и таймкод в ±2 секунды 4/21; TP15, FP5, FN6, TN14. Для VLM используется заново вычисленный calibrated CV replay `vlm_cv_baseline_af24b8b.json`, совпадающий с сохранённой калибровкой main. В нём у X39 исключён старый ложный safe-эпизод; бинарные показатели от этого не меняются.

На этом наборе можно измерять изменение качества разработки. Авторские аннотации задают первичный тип; дополнительные находки в положительном видео требуют отдельной проверки и не становятся автоматически подтверждёнными или ложными. Для известных чистых видео все добавленные события учитываются как ложные добавления. Отдельно считаются тип без времени и **то же событие с правильным типом и временем**; совпадение этих двух признаков у разных событий не засчитывается совместным попаданием.

Новой съёмки у пользователя пока нет. Публичный поиск казахстанских банковских видео нашёл [запись Alfa-bank в материале Tengrinews](https://tengrinews.kz/crime/video-ogrableniia-alfa-banka-v-almaty-pokazali-v-sude-326422/) и [сюжет 24KZ](https://24.kz/ru/tv-projects/dezhurnaya-chast/754527-10-tysyach-dollarov-edva-ne-ushli-moshennikam-pensionerku-spasla-kassir-banka-dezhurnaya-chast). Подтверждённого разрешения повторного использования и ручной gold-разметки нет; видео не скачивались и в benchmark не включены. Проверка нового ракурса остаётся незавершённой. Условия подготовки независимого набора и его метрики описаны в [angle-holdout.md](angle-holdout.md).

Локальная форма `var/manual-angle-review-2026-10-17/index.html` позволяет человеку назначить реальные камеры и группы съёмки для 40 уникальных старых видео. Разметка камер сама по себе не превращает development-видео в новый holdout. Форма и кадры остаются локальными.

## Development-пилоты Qwen3-VL

Одни и те же восемь уникальных клипов: пять положительных и три известных чистых. В этом подмножестве CV имеет TP2/FP0/FN3/TN3, основной тип 0/5 и совместное попадание того же события по типу и времени ±2 с — 0/5. Это выбранные трудные примеры, а не оценка полного набора или нового ракурса.

| Вариант | Основной тип | Тип + время ±2 с | Новых событий на чистых | TP / FP / FN / TN |
| --- | ---: | ---: | ---: | --- |
| V1: прямой выбор из 11 типов | 2/5 | 0/5 | 3 на 3 клипах | 4 / 3 / 1 / 0 |
| V2: семь positive-action типов | 2/5 | 1/5 | 6 на 3 клипах | 4 / 3 / 1 / 0 |
| V3: физические и обычные действия, индексы сначала | 0/5 | 0/5 | 0 | 2 / 0 / 3 / 3 |
| V4: действие сначала, поиск по всем кадрам | 1/5 | 0/5 | 0 | 3 / 0 / 2 / 3 |

V1 и V2 отклонены из-за ложных добавлений на всех трёх чистых примерах. V3 не добавил ни одного события. V4 добавил один правильный первичный тип (еда/напиток), но его пик отличается от первичной метки на 2,8 с; совместного попадания нет. Ноль ложных добавлений на трёх клипах не устанавливает precision на 19 чистых или независимом наборе. Дополнительные события положительных клипов не считаются автоматически подтверждёнными.

Все четыре прогона завершились 8/8, сохранили исходные CV-события без изменения и прошли проверку неизменности кода/KB. V4 использовал восемь model calls: тёплое дополнение в среднем 21,45 с, максимум 27,06 с; CV replay, startup и полный evidence pipeline в эти времена не входят. Числовые отчёты сохранены локально под `var/runs/vlm_pilot_v{1,2,3,4}.comparison.json`; приватные ответы и кадры не входят в Git.

`--action-contrast` у probe включает экспериментальный `physical_action_search_v4`: он различает физические целевые действия и обычные альтернативы, затем сопоставляет только разрешённые действия с проверенным каталогом. Сгенерированные фазовые описания являются шаблонным переводом выбранного действия, а не независимым визуальным подтверждением. Owned opt-in runtime использует тот же action decoder V4; backend injection остаётся прямым тестовым seam. Профиль **не утверждён по качеству и остаётся выключенным по умолчанию**. Новые рабочие задачи перечислены в [vlm-next-tasks.md](vlm-next-tasks.md).


Отдельный V4-прогон всех известных чистых видео завершён: 20 файлов / 19 уникальных содержимых, 0 новых событий и 0 ошибок enhancement. ## Полный Qwen3.5 V4: результат и решение

## Контроль native-video представления движения

Отдельный синтетический контроль использовал два простых пути красного круга: движение вправо и движение вправо с последующим разворотом влево. Для каждого сравнены 12 stills, native-video из 24 повторов тех же 12 кадров и native-video из 24 настоящих последовательных кадров. Во всех вариантах проверены 2640 визуальных токенов, реальные индексы известного синтетического источника 4 FPS и отсутствие дополнительного decode/sampling/URL-вызовов. Модель загружалась одна, вызовы выполнялись последовательно.

Все шесть вызовов завершились, направление правильно выбрано в 3/6: каждый формат распознал движение вправо, каждый перепутал название направления разворота. Результат 1/2 в каждом формате не подтверждает преимущество native-video. Это малый контроль выбора direction enum; он не устанавливает причину ошибок банковских действий и не доказывает отсутствие понимания движения. Продуктовый видеовход не менялся. Артефакт: `var/runs/native_video_motion_control_qwen35_v1.json`.

Для будущего реального native-video опыта требуются фактически декодированные source indices и FPS, а также явный контракт временных групп. Текущий `Frame(timestamp_s,path,pts_s)` этого не хранит; округлённый запрошенный timestamp и EOF fallback нельзя выдавать за фактический source index. Это отдельная задача до сравнения на реальных клипах.

## Разработка второго визуального прохода

Precision по видео у полного V4 — **17 / (17 + 7) = 70,8%**, у CV — **15 / (15 + 5) = 75%**. Это бинарная метрика наличия нарушения в видео, а не точность типов или event precision. Последнюю нельзя честно вычислить без полной разметки дополнительных эпизодов на положительных видео.

Экспериментальный `VerifiedActionBackend` проверяет предложения вторым запросом, не сообщая ему выбранное действие, тип, confidence, текст CV или gold. Общие deadline и лимит **четырёх физических обращений** принадлежат видео; неподтверждённый текущий эпизод отбрасывается, CV сохраняется. Обычный V4 сохраняет лимит двух обращений. Новый профиль явно выбирается `--verify-actions` либо `ML_VLM_VERIFY_ACTIONS=1`; discovery по умолчанию выключен.

Перед полным новым прогоном выполнены диагностические тесты на восьми специально выбранных development-видео: пять известных чистых с шестью ложными добавлениями V4 и три положительных с прежними улучшениями типа. Первые proposal-ответы точно восстановлены из замороженного V4; только второй визуальный проход выполнялся заново. Каждый тест использовал **12 сохранённых proposal-попыток и 9 реальных GPU-вызовов**. Это не полная регенерация и не отдельный holdout.

| Тест | Замороженный source | Валидные ответы без подтверждения | Ошибки формата | Сохранённые улучшения типа |
| --- | --- | ---: | ---: | ---: |
| P1: таблица примитивов | `c49cb5a` | 0 | 9, неверные номера кадров | 0/3 |
| P2: точные номера в JSON Schema | `5ee5934` | 7 | 2, противоречия повторного кадра | 0/3 |
| P3: уникальные anchor-кадры | `121b8d1` | 7 | 2, противоречие actor/role | 0/3 |
| P4: цельные физические факты | `16bb009` | 5 | 0 | 2/3 |
| P5: те же факты, все 12 кадров контекста | `16bb009` + отдельный harness | 6 | 0 | 2/3 |

Во всех тестах исходные CV-события и fingerprints сохранены. **Нулевые добавления при потере всех улучшений не проходят критерий качества.** P1 также не доказывает визуальное отсеивание ложных событий: все ответы отказали по формату. В P3 второй запрос получает только объединение уникальных исходных кадров начала/пика/конца, максимум шесть; повторный peak=end описывается один раз и разворачивается локально. Времена принятой находки всегда остаются исходными.

Таблица из независимых полей может оказаться неоднозначной даже при правильном выборе enum: предмет способен одновременно касаться руки и рта. Это причина проверить компактные цельные физические факты вместо ослабления проверки нужного действия. Санитизированные ответы модели остаются гипотезами, а не независимой истиной. Артефакты тестов: `var/runs/vlm_v5_screening_p{1,2,3}.screening-details.json`.

`CompactVerifiedActionBackend` сохраняет тот же общий бюджет, lifecycle и исходные времена находок, но запрашивает цельные физические факты и явные `yes/no/unknown` для непрерывности кассира и предмета. Действия с последовательностью требуют подтверждённых prerequisite/consequence и непрерывности; еда — полного видимого факта приёма пищи в peak. Во всех эпизодах одинаковые варианты физических фактов, обычных действий и unknown. Выбранный первым проходом тип/действие/confidence не передаются. Новый профиль включается явно через `--compact-verify-actions` либо `ML_VLM_COMPACT_VERIFY_ACTIONS=1`.

P4 вернул одежду и приём пищи, но также принял два ложных события на чистых видео. Оба прохода выполняет одна и та же модель: повторение ошибки возможно и при скрытом от второго запроса первом решении. P5 менял только набор кадров второго запроса, сохраняя atoms/parser/gates; один из этих ложных эпизодов исчез, прирост типов остался тем же. Дополнительная стоимость полного контекста не оправдала его включение в runtime. Отдельный ignored harness и его SHA зафиксированы в `var/runs/vlm_v5_screening_p5.screening-details.json`; production source не менялся.

Дополнительный условный replay P4 через настоящие `discover_types`, overlap/gap guards, резервирование CV slots и `assemble.select` проверил общий порог добавлений:

| Общий confidence gate | Новых событий | На известных чистых | Сохранённые улучшения типа |
| --- | ---: | ---: | ---: |
| 0,70 / 0,90 | 4 | 2 | 2/3 |
| 0,95 | 2 | 0 | 2/3 |

Все выбранные CV-события сохранены точно; dummy frames и сохранённые ответы не запускали модель или decode. Это результат **только выбранных восьми development-видео**, не проекция на оставшиеся 32. Весь прежний прирост ещё не сохранён: добавление ключа осталось неподтверждённым.

Для замороженного полного прогона выбран focused compact-профиль с `--min-confidence 0.95`. Gate принадлежит owner после визуальной проверки; proposal cutoff и число вызовов не меняются. Параметр также доступен в `configure_discovery(min_confidence=...)` и `ML_VLM_MIN_CONFIDENCE`; default остаётся 0,70. Значение 0,95 — **настройка на development-данных, не откалиброванная вероятность и не production recommendation**. Discovery остаётся выключенным по умолчанию.

Воспроизведение полного development-прогона, с новым путём результата:

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python -m ml.tools.vlm_type_probe \
  --model models/Qwen3.5-4B-MLX-4bit \
  --python var/venvs/vlm-mlx/bin/python \
  --baseline var/runs/vlm_cv_baseline_af24b8b.json \
  --out var/runs/vlm_compact_fresh.json \
  --compact-verify-actions --min-confidence 0.95
```

Без `--only` проверяются все 42 файла с повторным использованием двух точных дублей. CV берётся из указанного baseline, не вычисляется заново; полный production pipeline и evidence этим benchmark не измеряются.

## Полный fresh compact V5: ложные добавления убраны, прирост сохранён частично

Полностью заново выполнен V5-профиль на всех **42 файлах / 40 уникальных содержимых**; второй модельный проход запускается условно для подходящих предложений, frozen ML/KB source `7c9d350fcd2e31bdcc9af34ee4da47697cce0545`, тот же Qwen3.5-4B checkpoint, compact policy `physical_action_search_v4_blind_physical_atoms_v4`, общий owner gate 0,95. Это отдельный завершённый development benchmark, а не результат переноса ответов P4/P5. Два точных дубля переиспользовали inference; конфигурация, модель, исходные файлы и source fingerprints проверены.

| Метрика на 40 уникальных видео | CV | V4 | Compact V5, gate 0,95 |
| --- | ---: | ---: | ---: |
| Precision по видео | 75,0% | 70,8% | **76,2%** |
| TP / FP / FN / TN | 15 / 5 / 6 / 14 | 17 / 7 / 4 / 12 | **16 / 5 / 5 / 14** |
| Первичный тип на положительных | 9/21 | 12/21 | **11/21** |
| То же событие: тип + время ±2 с | 4/21 | 5/21 | **5/21** |
| Бинарная accuracy | 29/40 | 29/40 | 30/40 |
| Новых событий на 19 известных чистых | — | 6 | **0** |

Все шесть прежних ложных добавлений VLM исчезли; исходные пять ложноположительных видео CV остались. Исходные CV-события сохранены точно на всех 42 файлах. Всего V5 добавил два события: одежду/личные вещи и приём пищи. Первое совпадает с первичной меткой по типу и времени; второе совпадает по первичному типу, но не проходит ±2 с. Полного inventory дополнительных эпизодов нет, поэтому event precision по-прежнему не измерен.

**Сохранены два из трёх прежних улучшений первичного типа.** Событие ключа на X-22 второй проход не подтвердил. Относительно V4 потеряно одно TP, FP стало на два меньше; joint gain сохранился. Требование сохранить весь прежний прирост не выполнено, поэтому профиль остаётся opt-in и **выключенным по умолчанию**. Разница precision на этих 40 повторно использованных видео не устанавливает статистическую значимость, калибровку или качество нового ракурса.

Выполнено **66 физических вызовов**: 52 proposal и 14 verifier, общий лимит четырёх на уникальное видео соблюдён. Все file transactions завершены, нет timeout, budget exhaustion или enhancement fallback. Три proposal-окна в двух файлах отклонены с `action_order_unobserved`; это отказ от добавления, а не успешное отрицательное визуальное подтверждение. Ошибок формата второго прохода не зарегистрировано; сохранённые verifier diagnostics охватывают только последний запрос каждого видео и не выдают полный inventory всех окон.

Тёплое дополнение: mean **37,41 с**, median 31,67 с, max 64,94 с на 40 уникальных видео; startup **3,92 с** отдельно. CV берётся из frozen replay, evidence не входит. Полная suite замороженного V5 source: **1754 passed**; Ruff и whitespace checks прошли. Числовые результаты: `var/runs/vlm_qwen35_full_v5.comparison.json`, сопоставление V4/V5 — `var/runs/v5_numeric_review.{json,md}`. Они остаются локальными; приватные кадры и ответы в Git не попадают.

Два независимых пересчёта подтвердили метрики. Отдельный аудит прошёл **28/28 проверок целостности**. Воспроизведение настоящих `discover_types`, runtime gap/slot guards и `assemble.select` совпало с fresh probe на **42/42 файлах**: все сохранённые типизированные findings восстановлены точно, оба принятых Candidate совпадают полностью. Replay не загружал ML runtime, не декодировал видео и не рендерил evidence; wall-clock deadline этим не проверен. Артефакты: `var/runs/vlm_qwen35_full_v5.independent-review.{json,md}`, `var/runs/vlm_v5_selection_replay.{json,md}`.

Три отклонённых proposal-окна и их `action_order_unobserved` полностью совпадают с V4. Поэтому снижение чистых добавлений 6→0 нельзя объяснить новыми отказами формата; при этом согласие двух проходов одной модели не доказывает независимую визуальную истину. Общий strict gate «ни одного invalid window» не пройден, как и требование сохранить все прежние правильные типы.

Отдельный настоящий compact К2 job на X-46 вернул ответ за **185,14 с**, startup **4,58 с** отдельно; внешний watchdog 440 с не сработал. Но выполнена лишь **одна физическая попытка**, выбранных CV-событий, новых VLM-событий и JPEG было **0**. Статус успешности первого модельного ответа этим harness не сохранён; причина отсутствия второго прохода неизвестна. Согласованность пустого ответа и стабильность source/KB/model/input подтверждены, а **покрытие второго прохода, непустого CV retention, добавления и JPEG evidence — нет**. Такой smoke не подтверждает dataset-прирост в полном job или SLA. Числа и отдельные ограничения покрытия: `var/runs/vlm_qwen35_full_v5_job_smoke.{json,coverage.json}`.

## Проверка более крупного Qwen3.5-9B

Локально подготовлен `mlx-community/Qwen3.5-9B-4bit`, pinned revision `8b2b98c00a6b4d291155e4890773ca8f769aee53`. Оба shard SHA256 и структура checkpoint независимо проверены; лицензии и противоречивые заявления исходной model card о Base/Instruct зафиксированы в реестре. Исторический revision входа конвертации неизвестен. Synthetic multi-image контроль прошёл **21/21**, startup 8,75 с. Это совместимость, не качество нарушений.

До quality-вызовов записан локальный протокол: тот же frozen ML/KB source, compact policy, gate 0,95 и бюджет; сначала заново проверить три прежних улучшения, затем при сохранении **3/3 типов и прежнего joint** перейти к пяти чистым контролям и полному 40. Три положительных случая заранее выбраны из development-набора и не оценивают precision.

9B-профиль выполнен заново без сохранённых proposal-ответов; второй проход запускался условно: **три видео завершены, пять физических вызовов, ноль runtime errors**, исходный CV сохранён точно. Результат — **2/3 первичных типов, 1/3 joint**: одежда и еда сохранены, ключ не найден. Качество на этой выбранной тройке не улучшилось относительно 4B V5; обязательный gate 3/3 не пройден. По протоколу чистый и полный 9B benchmark не запускались. Полный результат 76,2% выше относится только к **4B V5 на 40 видео**, а не к 9B. Общая память и full-job SLA 9B не измерены.
