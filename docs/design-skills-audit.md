# Проверка дизайн-навыков GitHub

Дата: 17.10.2026. Статический просмотр перечисленных файлов и структуры каталогов. Изначально выполнена проверка без установки. По последующему запросу пользователя установлены frontend-design и web-design-guidelines; сторонние скрипты и бинарники не запускались. Проверка относится к просмотренному содержимому, а не к любым будущим изменениям репозиториев.

## 1. Anthropic — frontend-design: рекомендуется

Источник: https://github.com/anthropics/skills/tree/main/skills/frontend-design

Просмотрены полный SKILL.md и список файлов каталога (SKILL.md, LICENSE.txt). Навык посвящён контексту продукта, типографике, композиции, осмысленной анимации и самокритике. Он прямо разбирает повторяющиеся признаки шаблонного AI-дизайна.

В просмотренных инструкциях нет команд установки/выполнения, запросов секретов, отправки файлов, отключения защит или обхода разрешений. Скриптов в каталоге нет. Риск ниже, чем у навыков с исполняемыми помощниками. Перед установкой следует зафиксировать commit и повторно проверить именно устанавливаемую версию; main изменяемый.

## 2. Vercel — web-design-guidelines: рекомендуется с контролем внешних правил

Источник: https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines

Просмотрены полный SKILL.md, список каталога (один SKILL.md) и внешние правила:
https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md

Помогает проверять доступность, фокус, формы, адаптивность, анимацию и производительность. Это дополнение к художественному направлению, а не его замена.

В просмотренных текстах не обнаружены инструкции по передаче файлов или секретов, запуску shell-кода или обходу ограничений. Внешняя загрузка правил явно указана в навыке. Риск: правила на main могут меняться независимо от установленного SKILL.md. Их нужно проверять при каждом обновлении либо использовать отдельно проверенную фиксированную копию. Формулировки оформления, рассчитанные на английский интерфейс, не следует механически применять к русскому.

## 3. Impeccable: перспективен, стандартную установку пока не рекомендую

Источник: https://github.com/pbakaus/impeccable
Зафиксированная версия дерева: 6af45ac9a5eb8792f033d3242f52e99812fd91fa.

Просмотрены README, полный skill/SKILL.src.md и skill/scripts/impeccable; получено полное дерево GitHub (truncated=false). Это НЕ полный аудит репозитория, Rust-движка, npm-пакета или распространяемых бинарников.

Полезные направления: critique, distill, polish, typeset, layout. Однако текущий пакет уже не является простым набором Markdown-файлов:

- SKILL.src.md требует вызвать scripts/impeccable context.
- Launcher выполняет бинарник из заданного окружением пути, соседнего каталога, пользовательского кэша или PATH.
- При отсутствии движка может скачать его из GitHub Releases, записать в пользовательский кэш, сделать исполняемым и запустить.
- Для свежей загрузки проверяется SHA-256 по sidecar-файлу того же канала публикации. Это проверка соответствия скачанного файла, а не независимое доказательство безопасности.
- README описывает установку хуков для автоматического запуска проверок после правок UI и изменение конфигурации провайдера.

В просмотренном launcher не найдено явной отправки исходников или секретов. Однако без проверки движка и хуков нельзя делать вывод о всём пакете. Не запускать npx-установщик только на основании популярности репозитория.

## Выбор для проекта

Frontend-design от Anthropic — основной кандидат для визуальной работы. Web-design-guidelines от Vercel — дополнительная проверка UX и доступности. Impeccable — отложить до отдельного аудита исполняемых компонентов либо выбрать проверенную текстовую версию с фиксацией commit.

Перед каждой будущей установкой: смотреть весь устанавливаемый каталог и транзитивные инструкции, фиксировать источник и commit, проверять команды, сетевые адреса, хуки, доступ к секретам и записи вне проекта. Обновление навыка требует повторной проверки. Наличие известного автора само по себе не заменяет аудит.
