# Официальные тексты

Здесь хранятся текстовые снимки восьми официальных источников из [реестра](../sources.md), проверка / загрузка от 17.10.2026. Футеры источников: документы по состоянию на 14.10.2026, база обновлена 16.10.2026; полнота законодательства на 17-е не заверяется. В [candidates.json](candidates.json) — 14 кандидатов правовых оснований (8 + 6), в [type-mapping.json](type-mapping.json) — аналитическое сопоставление 32 общих типов. Подтверждённых детекторов нет. Закон об охранной деятельности остаётся фоновым источником без кандидатов событий.

## Формат хранения

Для каждой проверенной версии используется каталог `<ID>/<дата-проверки>/`, где дата имеет формат `ГГГГ-ММ-ДД`. В `text.md` сохранён полный `article` на языке источника: заголовки, пункты, подпункты, сноски и приложения. Таблицы сохранены HTML-разметкой с объединёнными ячейками; ссылки вне таблиц представлены их видимым текстом. Заголовок фиксирует реквизиты, URL, дату проверки, редакцию, статус, область применения и происхождение снимка. Извлечение выполнено локально через Python / lxml, без OCR. После маркера `<!-- BEGIN OFFICIAL ARTICLE -->` находится полный извлечённый текст источника.

Исходные HTML и пять инфокарточек сохранены побайтно в игнорируемом `data/legal-source-backup/`, а не в публичном дереве `kb/legal/`. В Git остаются официальные URL, исторические SHA256 и сведения происхождения.

[manifest.json](manifest.json) хранит ID, реквизиты, официальные URL, дату проверки, статус и его основание, редакцию и путь к текстовому снимку. `text_sha256` защищает отслеживаемый файл; `retrieved_html_sha256` и, при наличии, `retrieved_metadata_sha256` описывают ранее загруженные HTML и инфокарточки. Это разные артефакты, их хеши не взаимозаменяемы. `snapshot_anchor_ids` — индекс 95 используемых якорей, извлечённых из исходного `article` перед удалением HTML из Git; `reference_anchors` — используемые опорные ссылки. `snapshot_format: official_article_text_with_preserved_tables` и `anchor_verification: historical_html_extraction_not_live_dom_validation` явно ограничивают проверку. `documents_as_of` и `portal_updated_on` воспроизводят даты футера. Расчётные даты введения №53 и закона о банках помечены расчётами, не полями карточки. Пути отсчитываются от `kb/legal/`.

[candidates.json](candidates.json) — отдельный от таксономии список объектов: `id`, `source_id`, `status`, `clause`, `url`, `anchors`, `quote`, `subject`, `conditions`, `observable_facts`, `cannot_infer`, `mapping_status`. `quote` — непрерывная точная цитата, нормализованы только пробелы; она может включать несколько последовательных абзацев. Первый `anchors` совпадает с якорем URL, остальные фиксируют процитированные абзацы с якорями. У второго абзаца п.21 №14 собственного якоря нет, но он полностью включён в цитату. Поля `type_id` нет.

Цитаты сверять с официальным документом, включая вводные части, номера и вложенные подпункты. Ошибки извлечения и непрочитанные фрагменты отмечать явно; непроверенный OCR не считать точной цитатой. Пересказ и комментарии отделять от официального текста. При обновлении редакции сохранять прежнюю копию и указывать актуальную в реестре.

## Кандидат и подтверждённая привязка

**Кандидат** — источник или пункт для дальнейшей проверки. Его применимость к конкретной ситуации ещё не установлена; он не служит основанием для утверждения о нарушении.

**Подтверждённая привязка** — проверенная связь точного пункта с согласованным типом. Для неё должны быть записаны субъект, условия применения, наблюдаемый признак и ограничения вывода, дата и автор проверки. Такая привязка не подтверждает нарушение в конкретном видео автоматически.

Порядок проверки: **официальный текст → субъект / условия → наблюдаемый признак → подтверждённая привязка**.

По решению тимлида создан [каталог индикаторов](../violations.yaml): 27 активных и 5 исключённых (Д05, Д07, Д12, Д14, Д15), `owner_acceptance: indicator_policy_accepted`. Это принятие индикаторной политики, а не подтверждение правового вывода или реализации детектора. Все 14 записей отдельного пула норм сохраняют `status: candidate`, `mapping_status: draft_received_pending_review`: применимость к конкретным событиям не проверена.

У 26 активных индикаторов есть основной `rule`; вместе с 20 дополнительными ссылками это 46 цитат каталога. `document` содержит официальное название, `number_date` — реквизиты акта, `clause` — только номер пункта / подпункта, редакторские оговорки вынесены в `clause_note`. У активного Т04 ключа `rule` нет: `normative_basis: pending`, «нормативное основание уточняется». Т13 ограничен обычной банковской кассой по решению тимлида и использует только №14 п.8. Все записи имеют `implementation_status: not_implemented`; визуальной валидации нет. Эвристики, шаблоны и исключения описаны в [ограничениях](../../docs/limitations.md).

Каталог сохраняет К3: `version: 1`, английский `id`, кириллический `codex_code`, поле `summary`. Названия и summary нейтральны; стабильные ID и исторические `examples` сохранены. Принятие индикатора задаётся `enabled` / `policy_status`; у Т04 они сохраняют активность при `status: draft`. У остальных 26 `status: verified` относится только к проверке нормативной цитаты. Ссылки атрибутированы агенту Codex через `verified_by`, дату и область сверки. Все 27 шаблонов используют `{t}` / `{observation}` и контракт `ml/kb.py` из `origin/pr-31` (`215b51a`). Таблица ID, точные окончания шаблонов и пределы работы потребителей — в [документе интеграции](../../docs/catalog-integration.md).

## Аналитическое сопоставление типов

`type-mapping.json` содержит `metadata` и список `types` с кириллическими ID / названиями / группами. Для каждого типа указаны `legal_assessment`, `refs` (источник / пункт / URL / точная цитата), `required_context`, `observable_checks`, `limitations`, `pipeline_status: not_integrated` и отдельная `teamlead_policy`, связывающая запись с активным или исключённым типом каталога. Оценки сохранены: 19 `conditional`, 7 `no_direct_basis_as_named`, 6 `requires_nonvisual_evidence`. Они характеризуют правовое основание исходной формулировки, а не политику исключений или факт в видео; редакционное смягчение названия само по себе оценку не меняет. `supported_detectors=0`.

В `types[].refs` — 82 цитаты, в `metadata.temporal_refs` — 6 цитат переходных положений. Файл не содержит примеров видео, ID клипов, таймкодов и частных наблюдений. Проверка не зависит от игнорируемого `data/`. Обоснования и дальнейшие шаги — в [правовом review](../../docs/type-legal-review.md).

## Проверка целостности

Нужны Python 3.9+ и PyYAML 6.0.3 из [requirements](../../tools/requirements-legal.txt). Пример запуска из корня репозитория в отдельном окружении:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/requirements-legal.txt
.venv/bin/python -B tools/validate_legal_kb.py
.venv/bin/python -B tools/check_legal_catalog.py
```

Для проверки через неизменённый загрузчик PR31 можно предварительно извлечь его публичный исходник и передать путь:

```sh
git show 215b51ad608e884a2e035d1f459a04ec3dd3950a:ml/kb.py > /tmp/datathon26-pr31-kb.py
.venv/bin/python -B tools/check_legal_catalog.py --ml-loader /tmp/datathon26-pr31-kb.py
```

Проверенная ревизия загрузчика: `215b51ad608e884a2e035d1f459a04ec3dd3950a`; при другой ревизии результат не относится автоматически к этой проверке.

Сами проверки не обращаются в сеть и не анализируют видео. Для временной копии используется `--kb-dir /путь/к/kb/legal`; рядом должны находиться `/путь/к/kb/violations.yaml` и `/путь/к/kb/type-ids.json`. Достаточно скопировать эти файлы и `kb/legal/`; `data/`, `annotations.csv`, HTML и исследовательские материалы не нужны. `check_legal_catalog.py` автоматически создаёт такую временную копию, проверяет её и отклонение ошибочных вариантов каталога, затем удаляет копию.

Проверяются структура JSON и YAML, уникальные ID, ровно 32 аналитических ID Т01–Т17 / Д01–Д15 и каталог 27/5, enum / группы / статусы, официальные HTTPS-домены, наличие текстовых снимков и их `text_sha256`, точное вхождение цитат после нормализации только whitespace/NBSP и наличие ссылочных якорей в историческом `snapshot_anchor_ids`. Проверяются сохранённые даты среза, переходные цитаты, отсутствие `rule` у активного Т04, основание Т13, существенные исключения, ветви порогов и контракт шаблонов. YAML загружается через PyYAML SafeLoader с отклонением повторных ключей и небезопасных тегов. Успех — код 0, ошибка с пояснением — код 1.

Без исходного HTML валидатор не повторяет извлечение полного `article`, не проверяет DOM-якоря и не подтверждает доступность либо содержание живой страницы. Исторический индекс и хеши фиксируют происхождение снимка, а не новую сетевую сверку. Совпадение цитаты не подтверждает юридическую применимость, актуальность редакции на дату события или качество ML. Переходную редакцию п.16 №14 проверять отдельно: до 01.01.2027 применяется временная редакция по №88 от 24.12.2024.
