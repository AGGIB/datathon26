# Официальные тексты

Здесь хранятся локальные копии восьми официальных источников из [реестра](../sources.md), проверка / загрузка от 17.10.2026. Футеры всех снимков: документы по состоянию на 14.10.2026, база обновлена 16.10.2026; полнота законодательства на 17-е не заверяется. В [candidates.json](candidates.json) — 14 кандидатов правовых оснований (8 + 6), в [type-mapping.json](type-mapping.json) — предварительное сопоставление 32 общих названий черновика команды. Подтверждённых детекторов нет. Закон об охранной деятельности остаётся фоновым источником без кандидатов событий.

## Формат хранения

Для каждой проверенной версии создавать каталог `<ID>/<дата-проверки>/`, где дата имеет формат `ГГГГ-ММ-ДД`:

- `source.html` — исходный официальный HTML, сохранённый побайтно без изменений.
- `metadata.html` — официальная инфокарточка, сохранённая для пяти новых источников; её URL и SHA256 указаны отдельно.
- `text.md` — полный `article` на языке источника с заголовками, пунктами, подпунктами, сносками и приложениями. Таблицы сохранены HTML-разметкой с объединёнными ячейками; ссылки вне таблиц представлены их видимым текстом. В начале указаны ID, реквизиты, основной URL, источник загрузки, дата проверки, редакция, статус, область применения, SHA256 и способ извлечения. Извлечение выполнено локально через bundled Python / lxml, без OCR. После маркера `<!-- BEGIN OFFICIAL ARTICLE -->` находится только полный текст источника.

[manifest.json](manifest.json) — реестр для валидатора: `schema_version`, список `sources` с ID, реквизитами, официальными URL, датой проверки, статусом и его основанием, редакцией, относительными путями, SHA256 HTML / инфокарточек и опорными якорями `reference_anchors`. `documents_as_of` и `portal_updated_on` воспроизводят даты футера. Расчётные даты введения №53 и закона о банках явно помечены расчётами, не полями карточки. Все пути отсчитываются от `kb/legal/`.

[candidates.json](candidates.json) — отдельный от таксономии список объектов: `id`, `source_id`, `status`, `clause`, `url`, `anchors`, `quote`, `subject`, `conditions`, `observable_facts`, `cannot_infer`, `mapping_status`. `quote` — непрерывная точная цитата, нормализованы только пробелы; она может включать несколько последовательных абзацев. Первый `anchors` совпадает с якорем URL, остальные фиксируют процитированные абзацы с якорями. У второго абзаца п.21 №14 собственного якоря нет, но он полностью включён в цитату. Поля `type_id` нет.

Цитаты сверять с официальным документом, включая номера и вложенные подпункты. Ошибки извлечения и непрочитанные фрагменты отмечать явно; непроверенный OCR не считать точной цитатой. Пересказ и комментарии отделять от официального текста. При обновлении редакции сохранять прежнюю копию и указывать актуальную в реестре.

## Кандидат и подтверждённая привязка

**Кандидат** — источник или пункт для дальнейшей проверки. Его применимость к конкретной ситуации ещё не установлена; он не служит основанием для утверждения о нарушении.

**Подтверждённая привязка** — проверенная связь точного пункта с согласованным типом из каталога Алпамыса. Для неё должны быть записаны субъект, условия применения, наблюдаемый признак и ограничения вывода, а также дата и автор проверки. Такая привязка не подтверждает нарушение в конкретном видео автоматически.

Порядок проверки: **официальный текст → субъект / условия → наблюдаемый признак → подтверждённая привязка**.

По решению тимлида создан [каталог индикаторов](../violations.yaml): 27 активных и 5 исключённых (Д05, Д07, Д12, Д14, Д15), `owner_acceptance: indicator_policy_accepted`. Это принятие индикаторной политики, а не подтверждение правового вывода или реализации детектора. Все 14 записей отдельного пула норм сохраняют `status: candidate`, `mapping_status: draft_received_pending_review`: применимость к конкретным событиям не проверена.

У 26 активных индикаторов есть `rule` с документом, пунктом, точной цитатой, URL и ID источника; дополнительные ссылки доводят число цитат каталога до 48. У активного Т04 ключа `rule` нет: `normative_basis: pending`, «нормативное основание уточняется». Т13 ограничен обычной банковской кассой по решению тимлида и использует только №14 п.8. Все записи имеют `implementation_status: not_implemented`; визуальной валидации нет. Эвристики, шаблоны и исключения описаны в [ограничениях](../../docs/limitations.md).

Каталог совместим с существующим К3: `version: 1`, английский `id`, кириллический `codex_code`, поле `summary`. Принятие индикатора задаётся `enabled` / `policy_status`; у Т04 они сохраняют активность при `status: draft`. У остальных 26 `status: verified` относится только к проверке нормативной цитаты. Все 48 ссылок атрибутированы агенту Codex через `verified_by`, дату и область сверки. Таблица ID и пределы работы потребителей — в [документе интеграции](../../docs/catalog-integration.md).

## Предварительное сопоставление типов

`type-mapping.json` содержит `metadata` и список `types` с исходными кириллическими ID / названиями / группами. Для каждого типа указаны `legal_assessment`, `refs` (источник / пункт / URL / точная цитата), `required_context`, `observable_checks`, `limitations`, `pipeline_status: not_integrated` и отдельная `teamlead_policy`, связывающая запись с активным или исключённым типом каталога. Оценки сохранены: 19 `conditional`, 7 `no_direct_basis_as_named`, 6 `requires_nonvisual_evidence`. Они характеризуют правовое основание исходного названия, а не политику исключений или факт в видео; `supported_detectors=0`.

В `types[].refs` — 81 цитата, в `metadata.temporal_refs` — 6 цитат переходных положений. Файл не содержит примеров видео, ID клипов, таймкодов и частных наблюдений. Проверка не зависит от игнорируемого `data/`. Обоснования и дальнейшие шаги — в [правовом review](../../docs/type-legal-review.md).

## Проверка целостности

Нужны Python 3.9+ и PyYAML 6.0.3 из [requirements](../../tools/requirements-legal.txt). Пример запуска из корня репозитория в отдельном окружении:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r tools/requirements-legal.txt
.venv/bin/python -B tools/validate_legal_kb.py
.venv/bin/python -B tools/check_legal_catalog.py
```

Сами проверки не обращаются в сеть и не анализируют видео. Для временной копии используется `--kb-dir /путь/к/kb/legal`; рядом должны находиться `/путь/к/kb/violations.yaml` и `/путь/к/kb/type-ids.json`. Достаточно скопировать эти файлы и `kb/legal/`; `data/`, `annotations.csv` и исследовательские материалы не нужны. `check_legal_catalog.py` автоматически создаёт такую временную копию, проверяет её и отклонение 14 ошибочных вариантов каталога, затем удаляет копию.

Проверяются структура JSON и YAML, уникальные ID, ровно 32 аналитических ID Т01–Т17 / Д01–Д15 и каталог 27/5, enum / группы / статусы, официальные HTTPS-домены, наличие источника и локальных файлов, SHA256, совпадение полного извлечённого текста с `article`, точное вхождение цитат после нормализации только whitespace/NBSP и якоря обоих видов: `id` и `<a name>`. Также проверяются инфокарточки, даты футеров, переходные цитаты, отсутствие `rule` у Т04, основание Т13, сохранение исключений, ветви порогов и условные шаблоны. YAML загружается через PyYAML SafeLoader с отклонением повторных ключей и небезопасных тегов. Успех — код 0, ошибка с пояснением — код 1. Совпадение цитаты не подтверждает юридическую применимость, актуальность редакции на дату события или качество ML.

Переходную редакцию п.16 №14 проверять отдельно: на 17.10.2026 применяется временная редакция до 01.01.2027 по №88 от 24.12.2024. Валидатор не определяет юридическое действие нормы во времени.
