# Фронтенд — Рамазан

React + Vite + TypeScript, интерфейс в стилистике Forte. Совместим с К1 из [docs/contracts.md](../docs/contracts.md): загрузка → опрос статуса → вердикт, плеер, таймкоды, JPEG-кадры и нормативные основания.

## Запуск локального демо

Node.js 22.12+ (проверено на Node 24):

```sh
cd frontend
npm ci
npm run dev
```

Открыть адрес Vite из терминала. Без env-настроек dev-сервер использует локальную фикстуру: видео никуда не отправляется. Есть два сценария: два вымышленных эпизода с синтетическими иллюстрациями или отсутствие отмеченных эпизодов. Картинки в `public/demo/` созданы программно для проверки интерфейса и не содержат реальных кадров.

## Подключение API Наримана

Запустить бэкенд по корневому README. Затем:

```sh
cd frontend
cp .env.example .env.local
npm run dev
```

В `.env.local`:

```dotenv
VITE_API_BASE_URL=http://127.0.0.1:8000
VITE_DEMO_MODE=false
VITE_API_KEY=<ключ-выданный-командой>
```

Авторизация в API (ТЗ, раздел 10): UI передаёт заголовок `X-API-Key`. По умолчанию используется настроенный ключ UI. Его можно переопределить при сборке через `VITE_API_KEY` или в свёрнутых «Настройках подключения» интерфейса. Поле скрывает значение, пока пользователь не нажмёт «Показать». При доступном `localStorage` настройка сохраняется в браузере; если хранилище заблокировано, введённый ключ действует до закрытия страницы. Очистка поля возвращает настроенный ключ UI.

Поддерживаются MOV и MP4 до 200 МиБ. POST `/api/v1/analyze` принимает multipart с полем `file`; GET `/api/v1/jobs/{id}` опрашивается каждые 2 секунды после завершения предыдущего запроса. Отмена прекращает ожидание и запросы в браузере, сохраняя выбранный файл; серверная задача продолжает выполняться. «Новая проверка» очищает файл, результат и предпросмотр.

Клиент преобразует `violation` / `no_violation` в точные русские вердикты. Кадры `{timestamp_sec, image_base64}` проверяются и отображаются как JPEG data URL с собственными таймкодами каждого кадра; нормативные ссылки принимают только HTTP(S). Поля `rule` с null нормализуются. Статус обработки показывает русские названия стадий и `progress` от 0 до 1.

## Production на общем домене с FastAPI

```sh
cd frontend
npm run build
```

Сборка находится в `frontend/dist/`. Без VITE-переменных production использует API на том же origin и **не включает демо**. Если локально остался `.env.local` с адресом localhost, очистить `VITE_API_BASE_URL` или задать реальные параметры перед production-сборкой.

Запуск из корня командного репозитория (другие параметры бэкенда предварительно экспортировать по корневому README):

```sh
FRONTEND_DIST="$PWD/frontend/dist" uvicorn --factory backend.app.main:app_from_env --host 0.0.0.0 --port 8000
```

API поддерживает раздачу `FRONTEND_DIST` через FastAPI. `backend/Dockerfile` использует multi-stage сборку: сначала компилирует фронтенд через Node.js, затем копирует `dist/` в образ бэкенда с `FRONTEND_DIST=/app/frontend/dist`.

Для разных доменов указать HTTPS-адрес в `VITE_API_BASE_URL` при сборке. Бэкенд должен разрешать origin UI через CORS. Настройки VITE встраиваются при сборке; изменения env после сборки не действуют.

Для опубликованной демонстрации без API явно установить `VITE_DEMO_MODE=true` при сборке. Деморезультаты помечены как вымышленные.

## Ограничения интеграции

- В mock-режиме (`PIPELINE=mock`) выдаются тестовые события, нормы и кадры.
- MOV может содержать несовместимый с браузером кодек. UI объясняет ошибку, но транскодирование в MP4 требует согласованного endpoint от бэкенда.
- Mock-сценарий по имени `clean`: если имя загружаемого файла содержит подстроку `clean` (например, `cashier_clean.mov`), сервис возвращает статус `done` с вердиктом `no_violation`.
- Ожидание результата ограничено 5 минутами после загрузки; отправка — 120 секундами, отдельный запрос статуса — 15 секундами. Это клиентские ограничения, а не подтверждение скорости ML.

## Проверки

```sh
npm test
npm run build
npm run format:check
```

Тесты проверяют контракт К1: оба вердикта, JPEG base64, nullable-нормы, стадии и прогресс, failed, противоречивые и некорректные ответы. Браузерный прогон отдельно: файл, drag-and-drop, прогресс, ошибки ключа/сети, таймлайн, увеличенные кадры, ссылки, телефон и ноутбук.

## Структура

- `src/App.tsx`, `src/components/` — интерфейс.
- `src/hooks/useAnalysis.ts` — загрузка и опрос статуса.
- `src/api.ts` — HTTP, `src/api-contract.ts` — валидация и преобразование К1.
- `src/types.ts`, `src/config.ts`, `src/fixtures.ts` — типы, режим и демоданные.
- `src/components/ParticleBackground.tsx` — локальный интерактивный canvas.
- `public/` — локальные логотип и Open Sans с лицензией.
- `npm run format` — форматирование исходников и тестов.

Слайды, текст питча и сценарий демо находятся в `docs/`. Перед финальным выступлением заменить неподтверждённые цели реальными метриками команды и записать сквозное демо на боевом URL.
